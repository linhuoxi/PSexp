# PSexp v3.0 项目维护说明

这是一个 Windows x64 桌面工具，用于从 Photoshop 批量导出当前文档、画板、一级图层和切片。

本项目以 MIT 许可证开源，条款见 [LICENSE](LICENSE)。

## 编译

需要 .NET 10 SDK。运行本目录的 `编译.bat`：先跑自动化自测，再发布 Windows x64 自包含单文件 EXE，结尾打印产物路径。产物写在系统临时目录，不写入本仓库，也不会改动你机器上已有的程序。

作者的打包与发布流程（EXE 替换、回滚、Releases 上传）不在本仓库内。

## 本轮界面修正（2026-10-29）

- 导出参数卡片改为按可见内容自然收紧，参数与任务状态共用一个滚动区；窗口变矮或画板选项较多时整体滚动，底部执行按钮固定。移除参数区重复的进度行，切换模式重置滚动位置。修改前备份：`%TEMP%\PSexp-before-adaptive-layout-20261029-105427`。
- 质量刻度使用普通箭头光标，保留已有的轻微放大和拖动调节。
- 去掉关闭按钮悬停时对后代文字的白色覆盖；提示气泡明确使用正文前景色。标题栏按钮组独立贴右，外层描边改为叠加绘制，消除布局内缩与底边导致的偏移。
- 设置页使用独立的细滚动条主题：8 DIP 拖动区域、3 DIP 可见滑块，悬停和拖动仅改变透明度。侧栏固定留位，卡片不被滚动条遮挡。
- 修改前备份：`%TEMP%\PSexp-before-ui-polish-20261029-104138`。按用户要求仅源码修改与编译发布，不运行自测、不启动软件做窗口验收。

## 当前脚本执行方式（2026-10-29 更新）

- 五种导出模式现在全部通过 UXP `.psjs` 执行；文档信息和画板探测继续使用 COM / JSX。
- 快速、全部画板、选中项：使用三个 UXP 导出脚本，由 `receipt_task.psjs` 包装并回传明确完成状态和错误。
- 一级图层、切片：共用 `Resources/Scripts/export/layer_batch.psjs`，通过 UXP DOM 的 `saveAs.png/jpg(..., ..., true)` 保存副本。
- “切片”沿用历史含义：导出初始可见的一级图层并编号，不代表 Photoshop 原生切片区域。一级图层模式导出非背景、非“排除”前缀的一级图层，包括初始隐藏的目标，并保留背景和排除层的原始显示状态。
- 新批量脚本在 `finally` 中恢复所有一级图层可见性；按导出前快照筛选，修复切片模式只导出第一层的问题。
- 新批量脚本每完成一个文件写进度，恢复可见性后再写终态 JSON 回执。`UxpTaskWatcher` 等待明确回执，最长 30 分钟；失败时保留已完成文件并返回真实数量。
- 新批量模式直接写入用户导出目录，取消只停止等待，Photoshop 可能继续执行；取消或超时不清理仍可能被使用的脚本和回执目录。任务记录在 `%TEMP%\PSexp\tasks\<任务ID>`；明确结束后清理。
- `layers.jsx`、`slices.jsx` 保留作历史参考，当前导出调用链不使用，也不自动回退。UXP 独立脚本需要 Photoshop 23.5+；当前启动方式仍依赖本机 `.psjs` 文件关联可用。

修改前完整备份（源码、BAT、旧 EXE）位于 `%TEMP%\PSexp-before-uxp-20261029-084224`。

上一轮迁移验证（不是本次最终版本的验证结果）：53 项 .NET 自测、11 项 UXP 脚本行为测试；另使用最终混淆程序集重复运行 53 项自测，并检查发布 EXE 能创建主窗口和正常关闭。尚未在真实 Photoshop 文档中验收图像内容和兼容性。

发布工具改为固定 Obfuscar **2.2.50 稳定版**。原 `3.0.0-beta.19` 在本项目发布后出现嵌套类型加载错误；仅修改跳过规则未解决，稳定版验证通过。BAT 新增混淆后自测门槛，失败时不替换正式 EXE。

## 根目录规则

项目根目录 `PS导出/` 只允许保留以下三项：

```text
PSexp v3.0.exe       # 最新正式软件本体
一键编译发布.bat     # 测试、发布、清理的一键脚本
源码/                # 全部可维护源码和说明
```

不要把 `bin/`、`obj/`、`.pdb`、`.dll`、`.log`、临时备份、重复 EXE 或其他一次性文件放回根目录。
程序运行日志写入 `%AppData%\PsExporter\logs\psx.log`，不会写到软件根目录。

## 源码结构与关系

```text
源码/
├─ PSdodo/                         # 应用源码：真正组成软件的代码
│  ├─ PSdodo.csproj
│  ├─ Views/                       # 界面和窗口交互
│  ├─ ViewModels/                  # 页面状态和命令
│  ├─ Services/                    # 导出、设置、贴边收纳等服务
│  ├─ Core/                        # Photoshop 连接、脚本和日志
│  └─ Resources/Scripts/           # 内置 Photoshop 脚本
├─ tests/PSdodo.Tests/             # 自测源码：发布前检查应用代码
│  ├─ PSdodo.Tests.csproj
│  └─ Program.cs
├─ references/photoshop-scripts/   # 历史脚本参考资料，不直接编译进应用
├─ README.md                       # 人和后续 AI 的维护说明
└─ .gitignore
```

应用源码会被编译成 `PSexp v3.0.exe`。自测源码是独立的控制台程序，通过项目引用使用应用源码中的公共函数；应用源码不依赖自测源码。自测程序只在发布前运行，不会进入正式 EXE，也不会影响软件运行性能。

保留自测源码，不要只删除它的 `bin/` 和 `obj/`。以后修改窗口、导出、设置或动画时，先运行自测，可以防止旧功能被意外破坏。

## 窗口贴边收纳功能

设置中开启“窗口贴边自动收纳”后，将窗口拖到屏幕四边约 48 DIP 热区并松开，收纳为半露出图标，悬停或点击展开，移开后自动收回。

2026-10-29 本轮调整：

- 神灯网格由 `RequestAnimationFrame` 跟随渲染帧推进，取消 16ms 动画计时器和全局高精度计时设置。
- 每张捕获纹理复用 image / shader / paint，帧操作持有资源引用，防止交接和关闭时提前释放仍在渲染的资源。
- 收纳截图直接转移给展开过程，不再复制整张位图；捕获按实际 DPI 设置渲染比例，并限制到 150% / 约 200 万像素，控制高 DPI 下的捕获开销。
- 网格的纹理坐标和索引在同一尺寸下复用，每帧顶点独立，避免改写已提交的帧；尺寸改变时重建缓存。
- 真正收纳后停止状态动画和鼠标轮询，仅在展开状态以 50ms 周期检查鼠标离开。
- 动画交接期间保持状态锁，记录交接时的图标悬停；合成暂停和帧回调停止时提供超时兜底，避免一直卡在动画状态。
- 图标窗与动画窗独立于主窗口；图标窗设置为不激活的顶层工具窗，在收纳期间注册 Shell appbar 身份，不预留屏幕工作区；拦截其最小化和隐藏请求，并在 Explorer 重启后恢复注册。目标是保留 Win+D 后的边缘入口，不拦截全局快捷键。
- 复用辅助窗时更新尺寸和 DPI；主窗口停车到屏幕外时不重新套用主屏约束；显示器布局变化时解除收纳并把主窗移回可见工作区。
- 外部重复启动时先解除收纳再激活；退出时真正关闭辅助窗并注销 Shell 注册。

本轮另移除全部主动 Photoshop 成功/错误提示，移除设置中的“图层完成提示”；旧 JSON 字段只为配置兼容保留。

用户在修改中要求停止测试。此要求之后仅修改源码和编译发布，不再运行自测或进行窗口操作验收；最终版本的动画、Win+D 和导出效果由用户实测。修改前完整备份位于 `%TEMP%\PSexp-before-dock-fix-20261029-090213`。

相关实现主要在：

- `PSdodo/Services/EdgeSnapHelper.cs`：边缘判断、收纳坐标、精确感应区、弹簧动画曲线及 Skia 非线性神灯网格计算（CalculateGenieMeshData）；
- `PSdodo/Controls/GenieMeshControl.cs`：用于绘制 3D 纹理网格极化扭曲的 Skia 自定义控件；
- `PSdodo/Views/GenieAnimationWindow.cs`：独立透明动画承载窗，防止网格被主窗口矩形裁剪；
- `PSdodo/Views/DockIconWindow.cs`：收纳终态的独立透明图标窗，使用项目 ico 图标作为唯一展开触发器；
- `PSdodo/Views/MainWindow.axaml.cs`：拖动消息、高刷新定时器、实时纹理捕获、主窗/动画窗/图标窗状态切换、临时置顶、展开/收回交互；
- `PSdodo/Models/AppSettings.cs`、`ViewModels/MainViewModel.cs`：功能开关、设置持久化和收纳置顶状态。

## 一键编译发布

双击根目录的 `一键编译发布.bat`，或在项目根目录执行：

```powershell
.\一键编译发布.bat
```

脚本固定执行以下流程：

1. 按 `源码/dotnet-tools.json` 还原固定版本的 Obfuscar 本地工具；
2. 运行 `源码/tests/PSdodo.Tests/PSdodo.Tests.csproj` 的全部自测；
3. 进行 `win-x64`、自包含、单文件发布；默认关闭与 Photoshop 动态 COM/DOM 不兼容的裁剪；
4. 在 .NET 单文件捆绑前自动混淆本项目程序集，再使用 .NET 内置单文件压缩，并用混淆后的程序集重复运行自测；
5. 校验新 EXE 的存在、体积和复制结果，先保留回滚文件，再安全替换根目录的 `PSexp v3.0.exe`；
6. 清理 `bin/`、`obj/`、PDB、发布附属文件及混淆映射；任何步骤失败时尽量保留或恢复旧 EXE。

脚本会先切换到自身所在的项目根目录，所以从其他工作目录启动也能正确找到源码。编译电脑需要安装 .NET 10 SDK 并能从 NuGet 还原工具；最终 EXE 是自包含程序，终端用户无需安装 .NET。

默认使用稳定模式：不裁剪，但仍会混淆、单文件打包并启用 .NET 内置压缩（约 48 MiB），以保证 Photoshop 动态 COM/DOM 和 `DoJavaScript` 脚本桥可用。.NET 官方明确说明内置 COM 不兼容 trimming。仅用于实验时可在命令行先执行 `set PSexpEnableTrim=1` 再运行 BAT；实验裁剪版体积约 23 MiB，但不应作为日常生产版本。

不要手动把旧 EXE 改名冒充新版本。正式成品必须由脚本发布生成，并在发布后确认文件时间已更新、能够启动。

## 手动发布命令

```powershell
dotnet tool restore --tool-manifest .\源码\dotnet-tools.json
dotnet publish .\源码\PSdodo\PSdodo.csproj -c Release -r win-x64 --self-contained true --nologo -p:EnableReleaseObfuscation=true -p:PublishTrimmed=false
```

以上是保证 Photoshop 动态 COM/DOM 可用的稳定模式。仅用于实验裁剪时，才将末尾参数改为 `-p:PublishTrimmed=true -p:TrimMode=partial`；实验版不得替代日常正式版本。手动发布后也要删除构建目录和附属文件；更推荐直接使用 BAT。

## 导出可靠性

- 五种 UXP 导出都通过完成回执返回结果，软件展示成功、失败和输出数量，不主动调用 Photoshop 提示窗。
- 全部画板模式会等待预期画板数量完成。
- COM 脚本的 `success`、`count` 和 `error` 会参与应用结果判定。
- 取消 UXP 任务表示停止等待，Photoshop 仍可能继续执行已经触发的操作。
- 设置采用临时文件写入后替换的方式保存，失败时不会显示虚假的成功状态。

- 修改前备份：`%TEMP%\PSexp-before-ui-sync-20261029-092640`。遵照用户要求，本轮只编译打包，不运行自测或窗口实测。实际视觉、自动同步和置顶效果由用户验收。
