# 开发指南

本文中的路径均以 Git 仓库根目录为起点，即包含 `PSdodo/` 和 `编译.bat` 的目录。

完整产品行为、使用场景、脚本协议和配置字段见 [功能说明书](功能说明书.md)；介绍机器人与客服问答接入见 [AI 导览与问答](AI导览与问答.md)。两者按当前源码描述，发布包请核对对应版本。

## 构建与验证

需要 .NET 10 SDK。公开编译入口为 `编译.bat`，执行 .NET 自测后生成不包含 .NET 运行时的 Windows x64 单文件 EXE（运行需要 .NET 10 x64 Runtime），成品放在脚本旁边，中间文件写入 `%TEMP%/PSexp-compile/`。该入口默认不混淆、不裁剪，保留单文件压缩，不执行 Releases 上传。

单独构建和运行 .NET 自测：

```powershell
dotnet build .\PSdodo\PSdodo.csproj -c Release
dotnet run --project .\tests\PSdodo.Tests\PSdodo.Tests.csproj -c Release
```

安装 Node.js 后，还可运行 UXP 脚本行为测试（`编译.bat` 不自动执行这两项）：

```powershell
node .\tests\PSdodo.Tests\uxp-layer-batch.test.cjs
node .\tests\PSdodo.Tests\uxp-receipt.test.cjs
```

这些测试模拟 Photoshop DOM 和文件系统，覆盖图层筛选、命名、可见性恢复、部分失败和完成回执。发布前还应在真实 Photoshop 文档中检查图片内容、五种模式和兼容性；界面修改需要检查不同 DPI、窗口尺寸及交互状态。

## 模块

- `PSdodo/Views`、`ViewModels`：窗口交互、页面状态和命令。
- `PSdodo/Services`：导出、设置、Photoshop 联动与窗口收纳。
- `PSdodo/Core`：COM / UXP 桥接、任务回执、脚本注入及日志。
- `PSdodo/Resources/Scripts`：嵌入应用的 Photoshop 脚本。
- `PSdodo/Styles`、`Controls`：共享设计 Token、组件样式和自定义绘制。
- `tests/PSdodo.Tests`：独立自测程序，应用不依赖此项目，不打包进正式 EXE。
- `references/photoshop-scripts`：历史参考，非当前应用的编译输入；判断实际执行逻辑应查看 `Resources/Scripts` 和调用代码。

## 导出行为

五种导出模式使用 UXP `.psjs`；文档与画板探测使用 COM / JSX。快速导出使用等待完成的整画布 `saveAs`；全部画板及选中画板保留画板导出流程。图层由 `layer_batch.psjs` 按 `LayerExportRecursive` 选择一级图层或图层模式，图层模式通过 `LayerExportSelectedOnly` 选择 Photoshop 当前选中项或全部叶子图层；原生切片由 `native_slices.psjs` 独立处理，禁止以遍历可见图层代替切片。

一级图层按完整画布逐主体合成，顶层组整体输出；显示的排除项与真正背景保留为公共合成内容，隐藏的保持隐藏。真正背景按 `isBackgroundLayer` 属性识别，不看中文名称。公共水印、边框和底图仍遵循原层级、父级、蒙版与混合关系；没有创建盖印层、自动裁边或自动排列组合主体/背景的步骤。具体组织示例和实现依据见 [功能手册第 06 节](功能说明书.md#layers)。

图层导出按初始快照筛选目标，递归模式跳过图层组及排除分支，仅导出叶子图层；在 `finally` 中从子层向父组恢复全部可见性。原生切片读取 Action Manager 的 `slices` 元数据，筛选用户及图层生成的图像切片，整批只创建一个可复用的合成副本；每片在历史挂起期间按原始坐标裁剪并保存，随后通过 `resumeHistory(..., false)` 恢复完整画布，不累计裁剪历史。模态任务结束时关闭副本一次；支持的宿主使用 `registerAutoCloseDocument` 保证取消后的清理。原文档不参与裁剪或历史回滚。导出完成后通过 JSON 回执报告成功、失败及实际输出数量。取消只停止应用等待，不能保证 Photoshop 已终止；取消或超时后不得立即删除 Photoshop 仍可能使用的任务文件。任务目录位于 `%TEMP%/PSexp/tasks/`。

保留的旧导出 JSX 不表示当前调用链会自动回退到它们。修改导出逻辑时应同时核对实际调用、脚本和回执处理。

## 维护要求

- 保留现有自测；新增可测试逻辑时补充有意义的行为测试。
- 组件遵循 [UI 规范](UI规范.md)，同类尺寸和状态优先通过共享 Token / 样式修改。
- Photoshop 动态 COM / DOM 不适合随意启用裁剪；默认稳定发布关闭裁剪。
- 运行日志写入 EXE 同级目录的 `psx.log`。日志包含导出参数、任务编号、临时脚本与回执路径、执行结果和完整异常；失败任务文件会保留以便排查。上传日志或截图前检查个人路径与文档名称。
- 源码、测试、构建配置和有用的开发文档纳入 Git；构建产物、日志、账号凭据和个人工作记录不纳入 Git。
- 用户下载的 EXE 通过 GitHub Releases 附件分发，源码 Push 不会自动生成或上传 EXE。

作者本地外层目录中的发布脚本和内部历史记录不属于本仓库；克隆仓库后使用公开编译入口即可构建。

## 自动更新

`Services/UpdateSignature.cs` 以嵌入公钥强制验证清单签名，只从认证 payload 创建不可变元数据；`Services/UpdateService.cs` 负责受限 HTTPS 清单、流式下载、大小/版本/SHA256 校验及退出后的原子替换。`ViewModels/MainViewModel.Updates.cs` 负责自动检查、后台下载、手动安装、状态和取消。设置页及设置按钮上的更新提示由共享样式承载，更新过程写入 EXE 同级 psx.log。

目录开发版通过编译脚本更新；自动安装只适用于单文件发布版。客户端代码不包含 SSH 凭据；上传逻辑和本机连接配置位于仓库外层 release-tools/。服务器清单与包必须最后一致发布，不允许先发布清单再传 EXE。
完整签名协议、公开构建与私钥边界、发布机换机限制及服务器隔离见 [更新安全与发布签名](更新安全与发布签名.md)。源码仅包含公钥资源和公开签名工具，私钥位于本机 AppData 外部保管；当前未编译的新代码不会改变既有旧 EXE 的验证行为。

## 文档识别失败与 COM 连接

文档探测优先从 OLE Running Object Table 连接已经运行的 Photoshop，不通过 Activator.CreateInstance 启动 COM 服务器。注册候选按已运行进程路径匹配，匹配存在时避免连接其他安装版本；每个 CLSID 只尝试一次。连接失败记录 ProgID/HRESULT，并提示检查进程权限级别和宿主就绪状态。注册表只读，不自动重注册或关闭 Photoshop。

“无法读取 Photoshop 文档”与探针成功返回无文档分开处理；无效返回、COM 失败及轻量身份检查失败都不能显示成已确认无文档，也不能沿用旧目标继续导出。错误恢复后可刷新识别。连接失败不再走旧的 COM 创建流程，但运行实例是否能被当前会话访问仍需实机确认；本次仅核对日志和修改源码，未编译测试。

### COM 不可用时的 UXP 识别

若运行实例也无法通过 COM 获取（例如 0x800401E3），PhotoshopService 在当前进程内切换到独立 UXP 文档探针 document_info_uxp.psjs，通过 document.json 读取文档名、像素尺寸、完整文件路径、画板与原生切片信息。UXP 完整文件路径转换为父目录后才进入既有输出位置模型；云标识/未保存文档不冒充本地目录。这个探针不创建、保存或关闭 Photoshop 文档。

UXP 文件关联执行可能激活 Photoshop，所以仅在 Photoshop 已经位于前台且开启自动同步时按用户设置间隔串行刷新；不在 PSexp 窗口激活时派发，前一轮未结束不重入。启动识别、手动刷新和导出前刷新继续可用。成功后的脚本延迟清理由独立异步任务执行，不让 2 秒清理等待拖慢同步。任务成功后清理探针材料，失败/超时保留路径和日志。COM 错误及 UXP 回执都记录在 psx.log，不能把后续失败一律归因于权限。未编译实测，不据此声称已在所有宿主恢复。

切片 `FileName`/`SliceFilePrefix` 默认空，前缀不参与导出可用性判定；显式输入和清空均保存。原生切片脚本只在非空前缀后追加下划线，空值直接使用切片名或序号。

## 参数记忆与切片子文件夹

AppSettings 保留历史 default 前缀字段作为上次路径/格式/质量，补存 LastExportMode、LastArtboardPathOption、QuickImageName、LayerImagePrefix、SliceFolderName、LastSettingsSection 与 ShowSettingsOnStartup。完整快照写入所有当前用户参数，名称分模式存储；清空不被启动兜底改写。MainViewModel.ParameterMemory.cs 对连续输入使用 250ms 保存合并，窗口失焦/关闭调用 FlushParameterMemory。PNG 启动同时恢复 IsJpgFormat，避免质量行显隐与格式不一致。

切片文件夹为可选单级名称，校验后在输出根目录组合路径；ExportSlicesAsync 复制本次参数并用实际目录执行，不污染用户保存的根目录。空值直出、同名文件夹复用、文件冲突按原策略处理。新控件复用现有输入样式，错误就地显示。不恢复任务过程或 Photoshop 实时状态；未编译测试。

## 自动同步与键盘输入保护

源码没有注册全局热键或键盘钩子，也没有注入按键。实际日志曾显示 UXP 文档探针约每 0.8 秒派发，即使文档未变也重复进入 Photoshop 脚本引擎，有打断快捷键和编辑的风险。现改为只读检查最后输入时间和修饰键/空格/鼠标按钮的按下状态：Photoshop 在前台、键鼠无输入至少 1200ms、没有修饰键、空格或鼠标按钮按住时才允许自动探测。没有截获、吞掉、修改或记录按键内容。

UXP 通道将一段新操作合并为一次同步，未变化时不每轮派发，最长约 60 秒空闲校准一次；设置间隔控制检查频率，不代表每个间隔执行脚本。手动刷新和主动导出不受自动同步等待约束。窗口失活时只清编辑逻辑焦点，不调用窗口 Focus 抢回键盘焦点。以上为源码修改，尚未实机验证快捷键恢复情况。
