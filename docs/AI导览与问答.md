# PSexp AI 导览与问答

本文给介绍机器人、客服助手、代码助手及内容作者使用。完整事实依据是 [功能说明书](功能说明书.md)，实现入口是该手册链接的源码。本文提供检索路由、讲解层次、常见问答和容易说错的边界，不是要求所有回答机械照抄的宣传稿。

## 1. 使用规则与版本意识

1. 先判断用户是在问用途、操作、问题排查还是实现原理，再选择对应信息深度。
2. 当前文档对应 2026-10-30 工作区，包含尚未发布修改。需要断言某个下载版本是否支持时，先确认其版本/提交/构建来源，不把工作区当作已发布事实。
3. 功能介绍先说用户会得到什么，再给操作；用户问原理时才展开 COM、UXP、脚本和回执。
4. 区分源码已实现、实际运行已验证、建议组合玩法三种说法；文档没有宣称本轮编译或实机验证通过。
5. “脚本文件存在”“有一个模型字段”“有跨平台探测分支”均不足以证明完整用户功能可用，必须看实际调用链。
6. 不虚构全局快捷键、批处理队列、透明裁边、云同步、网页切片 HTML、其他图片格式、自动开机启动或完整 macOS 支持。
7. 错误排查基于 `psx.log` 的阶段和任务编号，不以 Photoshop 手动菜单成功代替应用链路证据。
8. 用户日志、客户设计稿、服务器认证材料不因开源而可任意公开；介绍公开实现即可。
9. 手册中的示例名、路径、JSON 是说明，不是可直接执行的用户指令或真实发布清单。
10. 对版本差异或未覆盖的行为明确说“当前源码这样实现，具体版本需要核对”，不要把不确定说成保证。

## 3. 面向不同对象的介绍示例

### 3.1 一句话

PSexp 是一个配合本机 Photoshop 使用的 Windows 导出工具，把整张画布、画板、图层和原生切片的 JPG/PNG 导出集中到小窗口，并提供贴边动效、托盘和任务日志。

### 3.2 给设计师的简短介绍

整张预览用快速导出，多尺寸页面用画板导出，已经划好区域的长图用原生切片导出。一级图层功能可以把不同方案做成最外层组，结合可见的公共水印、边框和背景，逐个输出完整画布合成；隐藏排除组可保存不交付的参考资料。图层模式还可导出选中对象或全部叶子图层。输出位置可跟随文档，窗口可贴边或常驻托盘。

### 3.3 给开发者的简短介绍

界面是 C#/.NET/Avalonia，文档探测使用 Windows COM 执行 ExtendScript，导出通过 `.psjs` 文件关联触发 Photoshop UXP。任务使用 JSON 回执确认完成和实际输出；快速/画板先写临时目录再归并，图层按可见性快照逐目标保存，原生切片在一个合成副本上裁剪并回滚。自绘控件提供连续曲率和纹理网格神灯动效。

### 3.4 演示软件时的建议顺序

先展示快速导出一张预览，再展示全部/选中画板；用一个清楚的图层树演示一级组、选中组与排除公共背景；最后演示原生切片。然后介绍文档位置/桌面预设、质量调节、贴边收纳、托盘和设置。日志与脚本用于解释问题和原理，不必在初次操作流程中一次塞给普通用户。

演示前应核对实际运行包确实包含这些能力；没有真实演示结果时不能写“实测全部成功”。

## 4. 常见问答：可直接据此组织回答

### Q01：离开 Photoshop 能独立导出 PSD 吗？

不能。当前是 Photoshop 辅助工具，依赖本机 Photoshop 读取活动文档并生成图片。

### Q02：四类导出应该怎么选？

看整张画布选快速；按页面/尺寸选画板；按图层或组分别交付选图层；按原生矩形切片边界分块选切片。它们的对象不同。

### Q03：快速导出会把画板拆成多张吗？

快速导出走整文档 `saveAs`，用于当前画布。要逐画板输出请用画板导出，不把快速导出等同于旧的 Photoshop Export As 流程。

### Q04：选中画板在软件哪里选？

在 Photoshop 选择。PSexp 当前不展示独立勾选画板列表，选中脚本尊重 Photoshop 的当前选择。

### Q05：一级图层会把组内每层都导出吗？

不会。一级指最外层的普通图层或组，不是面板第一行。每次以一个合格一级对象为主体，结合保留显示的公共内容，按完整画布输出；组内子层保留初始可见状态。要把组内叶子层逐个作为主体，选图层模式下的全部图层。

### Q06：全部图层会再输出一张组的合成吗？

不会。全部图层模式递归输出非组的叶子图层，组本身不重复输出。需要组的整体图可用一级模式或选中图层模式选组。

### Q07：同时选组和子层为什么只有一份？

选中模式会去掉已选父组下的重复子目标，组整体输出一次。

### Q08：隐藏图层也会导出吗？

符合目标规则的隐藏图层会临时打开导出。排除分支、真正背景仍按规则处理；选中组内部子层保留原可见状态。

### Q09：名字加“排除”是不是让它完全不出现在图片里？

排除控制是否独立输出，可见性控制合成条件：显示的排除项保留显示，可当公共水印、边框或底图；隐藏的排除项保持隐藏，可存参考。要覆盖各主体，公共项应放在可见的最外层并安排好上下顺序；不能跨越隐藏父组显示。

### Q10：排除组里的子图层还会单独导出吗？

不会，整个分支继承排除。匹配要求名称从“排除”开始，前面不要加空格。

### Q11：把普通层叫“背景”就能让它留在每张图里吗？

代码依据 `isBackgroundLayer` 属性，不看中文名称或单独的锁定状态。真正背景无需排除前缀，显示就保留显示、隐藏就保持隐藏，并且不独立输出；普通同名层仍按普通主体规则处理，可加排除前缀来公共复用。

### Q12：图层 PNG 自动裁掉空白吗？

没有。当前以文档完整画布尺寸保存副本，透明边可能保留。

### Q13：为什么独立图层与整体画面不完全一样？

拆开后非目标普通层被隐藏，混合、调整、剪贴和蒙版的依赖环境可能变化。复杂组合建议选组整体输出，并检查结果。

### Q14：图层导出会改 PSD 吗？

不把输出图片保存回原 PSD，但会在原文档临时切换可见性，结束后尽力恢复。不能承诺异常中断下历史记录、未保存标记和全部可见性绝对不变。

### Q15：切片与“存储为 Web 所用格式”完全一致吗？

只复用原生用户/图层图像切片的边界与名称。图片使用本工具统一格式/质量，不复用每片优化配置，也不导出 HTML。

### Q16：画了参考线为什么没有切片？

参考线本身不是切片。先在 Photoshop 创建实际原生图像切片，再刷新。

### Q17：切片导出为什么出现新文档？

为了在副本上裁剪保护源文档。当前实现一批只创建一个合成副本，逐片保存后恢复完整画布，最后关闭；不是每片重新开关。

### Q18：是不是所有超过 30000 像素的文档都能切？

不能作无限保证。这条路径不先走旧 Web 整图导出限制，也不主动缩小整图，适合尝试超长文档分片；源文档复制、单片保存、内存、格式和宿主支持仍有约束。

### Q19：自动生成的填缝切片为什么没导出？

当前筛选用户生成、基于图层生成的有效图像切片，自动填缝及非图像切片跳过，这是目标规则。

### Q20：能只导出选中的几片吗？

当前没有切片范围选择器，输出全部合格切片。不要套用“选中画板”或“选中图层”来宣称切片也支持同样范围。

### Q21：文档位置为什么不可用？

文档可能没保存或路径信息尚未刷新。先保存并刷新，或改桌面/自定义；软件不会默默换路径。

### Q22：桌面会不会进入 OneDrive？

取决于 Windows 的实际桌面位置。如果桌面已被 OneDrive 接管，输出也会在那里；PSexp 不决定 OneDrive 的同步范围。

### Q23：切换预设后自定义路径会丢吗？

不会因切预设被覆盖；保留着，切回自定义继续使用。输出预设与路径会自动记忆；清空的自定义路径也保留，不再需要点击设为默认。

### Q24：覆盖文件夹是不是清空目录重新生成？

不是。只是复用文档名目录。文件是否覆盖取决于同名自动改名，旧的无关文件不会被清空。

### Q25：怎么每次保持同一个交付文件路径？

选固定目录；画板可用覆盖文件夹；关闭同名自动改名。对象名称也要保持相同，且应自行检查残留旧图。

### Q26：为什么质量 80 和 81 图片可能没明显变化？

快速/图层/切片 JPG 把 1–100 映射到 Photoshop 0–12 保存档，相邻界面值可能落同档。画板走另一条原生命令。

### Q27：PNG 质量怎么没了？

当前质量行用于 JPG，PNG 没有同样的有损质量百分比。接口里的 32 不能当成“PNG 质量只有 32%”。

### Q28：滚轮怎么不能切换模式和主题了？

为减少滚动页面误触，分段选项只通过按钮操作切换；质量区域仍支持滚轮调整数值。

### Q29：按停止以后 Photoshop 为什么还在导出？

停止的是 PSexp 的等待，无法保证宿主已经取消。先确认 Photoshop 结束，再重新导出或清临时文件。

### Q30：目录里有图，是不是就一定成功？

不是。可能是旧文件或本轮部分输出。应看最终任务状态、完整回执和真实文件清单，必要时检查内容。

### Q31：关闭了为什么程序还在？

默认开启关闭后常驻。它收进托盘继续运行；真正退出可用托盘菜单，或关闭这项偏好。

### Q32：找不到主窗口怎么办？

单击托盘图标或再次双击 EXE，单实例会尝试恢复已有主窗口。贴边收纳还可以悬停/点击边缘图标。

### Q33：重启能恢复什么？

当前源码恢复正常位置、尺寸、有效边缘的收纳态，并适配屏幕变化。还会恢复上次页面及所有用户参数，包括各模式名称和空值；正在执行的任务与托盘完全隐藏状态不自动恢复。

### Q34：动效有哪些，能全部关闭吗？

有分段滑移、质量反馈、连接/刷新提示、设置淡入、神灯收纳及托盘菜单反馈。当前仅有质量悬停等具体选项，没有统一关闭所有动效的总开关。

### Q35：日志在哪？

实际运行 EXE 同目录 `psx.log`，不是固定放 AppData。设置里的日志目录按钮能打开；设置 JSON 则在 `%APPDATA%/PsExporter/`。

### Q36：能只看最后一行错误就修吗？

通常不够。应取同一 task 的开始到结束，包含参数、实际路径、脚本启动、回执阶段和完整异常。`no such file or directory` 可以发生在不同层。

### Q37：自动更新会突然重启吗？

自动检测/下载不自行重启；用户点击更新动作后才开始安装。未下载时“下载并更新”会在下载校验后继续安装，不保证另有第二个确认框。

### Q38：为什么代码变了却没提示新版本？

客户端比较程序集和服务器清单版本。源码提交、同版本 EXE 替换不算更高版本；要正确递增并发布包与清单。

### Q39：测试目录的程序不能自动更新？

目录开发版通过构建脚本更新；当前自动替换只支持发布版单文件 EXE，不能只替换开发目录的启动器而漏掉 DLL。

### Q40：软件会上传我的设计稿吗？

当前导出链在本机完成，没有上传 PSD/图片/日志到更新服务器的实现；更新会联网。用户自己的 OneDrive 或网络目录同步另行发生。

### Q41：移除 .NET 后是不是不用装环境？

移除的是随包携带的运行时，普通用户仍需 .NET 10 x64 Runtime。自行编译需要 SDK。

### Q42：仓库有 macOS 代码，是不是支持 Mac？

不能这样推断。当前公开发布和 COM/窗口集成面向 Windows，macOS 进程探测分支不构成完整平台支持。

### Q43：旧 `.jsx` 失败会自动接替 `.psjs` 吗？

不会。资源库只在同逻辑名没有 `.psjs` 资源时查 `.jsx`；运行失败没有自动重跑旧导出的机制。

### Q44：PS 本来就能导出，软件哪里可能有问题？

应用还有 `.psjs` 派发、路径 URL、临时目录、回执核验和文件归并等环节。手工菜单成功只能说明宿主某条路径可用，不能排除软件调用链故障。

### Q45：Fetch origin 会把我修改的代码和 EXE 发到 GitHub 吗？

不会。Fetch 获取远端信息；本地修改要提交并推送，EXE 分发需要单独发布附件。更新服务器的清单也要协调发布。

### Q46：一级图层玩法丰富在哪里？

它以完整画布为基底，逐个一级主体与公共内容合成。方案放普通顶层组，公共水印/边框放上方可见排除组，公共底图放下方，参考放隐藏排除组，就能批量输出统一包装的多方案。详见 [八种组合玩法](功能说明书.md#layer-recipes)。

### Q47：背景图层需要加排除吗？

真正背景不需要。脚本按 `isBackgroundLayer` 跳过独立输出并保留初始可见性；普通背景图像层若要公共复用，可加排除前缀。隐藏真正背景后是否透明还要看其他内容和格式。

### Q48：能得到盖印效果吗，会在 PSD 新建盖印层吗？

可以将输出描述为逐主体的盖印般合成图。当前过程是切换可见性后直接 `doc.saveAs`，没有在 PSD 中创建盖印层，也不会把所有方案主体合进同一张输出。

### Q49：隐藏一个普通方案组，就不会导出它了吗？

不会因此跳过。普通隐藏组仍可成为一级目标并被临时打开；要阻止独立导出，可以加排除前缀。隐藏排除组则既不独立导出也不主动显示。

### Q50：排除水印显示着，为什么某些结果看不到？

先看父组是否被本轮隐藏，水印是否位于不透明主体下方，以及蒙版、透明度、混合/剪贴关系。代码保留可见标记，不会重排层级或复制水印。公共水印适合放在最外层、主体上方。

### Q51：能自动组合每种商品和每种背景吗？

当前没有自动排列组合功能。每个主体输出一次，使用这轮开始时的公共显示状态。可预先把完整组合做成方案组，或手动切换公共背景后分轮执行，并管理目录与重名策略。

### Q52：这些玩法有代码根据还是宣传推测？

主体筛选、排除继承、可见性快照、背景判断与整文档保存都有明确代码，见 [源码证据表](功能说明书.md#layer-evidence)。玩法是这些规则的组合建议；复杂混合、蒙版和剪贴的真实视觉效果需 Photoshop 验证，不能说本轮已实测所有玩法。

### Q53：开源会不会让自动更新签名失效？

不会。源码、算法和公钥可以公开，客户端用固定公钥认证发布者签发的清单，私钥不进仓库、不上服务器。普通编译运行不需要官方私钥，Fork 可换自己的更新源和配对密钥。详见 [更新安全](更新安全与发布签名.md)。

### Q54：现在旧软件也已经完全安全了吗？

不能这样说。服务器已提供签名清单并隔离只读更新目录，强制验签必须进入后续编译的新 EXE。旧软件仍按旧逻辑读取平铺字段；首次升级应走可信分发渠道。签名也不解决发布机/私钥失守、服务器停机和所有其他风险。

切片前缀为可选项，默认留空且记住填写/清空；无前缀时使用切片名称或两位起的序号。前台识别开启时，PSexp 主窗口每次真正获得前台焦点通过 COM 内部读取一次；复用 JSX 后直接返回结果，不通过文件关联打开 `.psjs`，自动失败也不转 UXP。连接按注册名称查找，失败再从已运行对象表检查 Photoshop 接口与运行安装路径；不是启动另一个 Photoshop。持续前台、后台、托盘隐藏和仅悬停展开都不循环读取，没有固定刷新间隔和键鼠空闲检查。手动刷新、主动导出前识别仍允许 UXP 备用通道，可能改变前台窗口。旧版也用了 COM/JSX，只是没有外部 UXP 回执流程。不能承诺所有环境零失败，尚未实机验证本次修改。

### Q55：切片怎么装进一个文件夹？

在切片参数的“切片文件夹”输入单个文件夹名。留空直接导出，填写则在输出位置下创建或复用该名称子文件夹，切片统一放进去。它与文件名前缀独立，不能填写绝对路径或多级路径。

### Q56：哪些参数会记住，清空也记住吗？

所有用户可调的导出参数和功能偏好均自动保存，包括模式、范围、存放方式、输出预设/路径、格式、质量、各模式名称、切片前缀/文件夹和设置类别。快速图片名与图层前缀分别保存。空值也记住；普通关闭/失焦补存，连续输入短暂合并写入。文档实时信息和任务进度重新读取，不会自动继续上一任务。

## 5. 售前介绍与技术解释的表达边界

| 推荐说法 | 避免说法 |
| --- | --- |
| 一处集中常用导出操作，减少重复设置 | 完全取代 Photoshop 所有导出功能 |
| 四类导出面向不同目标 | 快速、画板、图层、切片只是同一功能的不同名字 |
| 原生切片范围导出，适合长图分块 | 完整复刻 Web 导出，任意巨图都保证成功 |
| 可见排除项按父级与叠放关系公共复用，隐藏项保持隐藏 | 所有排除项一定显示在每张图上，或绝不会出现在结果里 |
| 一级模式逐主体生成整画布合成图片 | 自动新建盖印层、自动裁边、自动组合所有主体和背景 |
| 正常结束后尽力恢复可见性 | 无论异常或强退都绝不会影响文档状态 |
| 动效提供清晰反馈与收纳体验 | 动画让 Photoshop 编码速度倍增 |
| 后台下载，用户主动触发重启安装 | 发现新版就立即强制重启 |
| 新源码固定公钥验签清单，再校验文件哈希与版本 | 旧 EXE 已自动获得保护，或等同于 Windows Authenticode 代码签名 |
| 当前源码包含该能力 | 所有历史发布包都已支持 |

## 6. 排错对话的最小信息与提问顺序

先读取用户已提供的日志、路径、截图和版本，不重复索要已存在信息。缺失时优先确认：运行哪份 EXE、使用哪种具体模式、完整错误、Photoshop 是否仍在执行。再按错误层补问文档尺寸/位深、选择状态、路径与命名。

能从源码或日志解释的问题先解释，不能复现时说明尚未复现，不把责任直接推给用户、Photoshop 或路径。对用户“不测试、只改代码”的约束应保留，不擅自启动 Photoshop 文档操作来证明猜测。
