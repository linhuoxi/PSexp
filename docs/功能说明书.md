## 01 产品定位与功能边界

### 01.1 PSexp 是什么

PSexp 是一个围绕 Photoshop 当前文档工作的 Windows 桌面图片导出工具。它把常用导出操作集中到一个小窗口：选择导出对象、输出位置、JPG/PNG、质量和文件命名，然后执行；不需要每次进入多个 Photoshop 菜单重复设置。

它依赖本机 Photoshop 完成文档读取和图片生成。PSexp 负责界面、参数组织、脚本调度、文件归并、任务反馈、日志与更新。它不是脱离 Photoshop 的 PSD 解析器，也不是图片编辑器。

### 01.2 最值得介绍的能力

| 功能编号 | 能力 | 实际价值 |
| --- | --- | --- |
| EXP-QUICK | 当前整张画布快速导出 | 随手发预览、检查当前合成画面 |
| EXP-ARTBOARD | 全部或当前选中画板导出 | 多尺寸、多页面设计一次交付 |
| EXP-LAYER | 一级图层、选中图层、全部叶子图层导出 | 主视觉变体、组件素材、分层交付 |
| EXP-SLICE | Photoshop 原生用户切片导出 | 按设计师已划好的区域输出长图分块等图片 |
| PARAM-DESTINATION | 文档位置、桌面、自定义目录 | 兼顾项目归档和临时交付 |
| WINDOW-DOCK | 四边贴边收纳、半露出图标、神灯动效 | 需要时展开，用完让出 Photoshop 工作区 |
| WINDOW-TRAY | 托盘常驻与快捷菜单 | 主窗口关闭后继续保留入口和后台任务 |
| WINDOW-RESTORE | 窗口位置、尺寸、收纳状态恢复 | 重启后延续上次的工作摆放 |
| UPDATE | 检测、下载并手动触发重启更新 | 减少重新下载和手动替换 EXE 的操作 |
| DIAG-LOG | EXE 同目录日志、失败任务诊断保留 | 根据任务编号和脚本回执定位问题 |
| UI-MOTION | 连续曲率圆角、分段切换、质量与状态反馈 | 给频繁使用的小工具提供清晰、有辨识度的交互 |

### 01.3 当前不应对外承诺的能力

- 当前公开构建目标是 Windows x64。存在 macOS 进程探测代码，不代表完整 macOS 导出链已经实现。
- 当前图片格式为 JPG、PNG，没有把 WebP、AVIF、SVG、PDF 等作为已实现导出格式。
- 面向 Photoshop 当前活动文档，没有目录内 PSD 批处理队列、跨文件无人值守任务或多 Photoshop 实例选择器。
- 没有把全局快捷键、命令行批量导出、开机自启动、云端图片同步列为现有用户功能。
- 切片不生成 HTML，不完整复刻“存储为 Web 所用格式”的全部选项。
- 没有对任意颜色模式、位深、超大尺寸、Photoshop 版本作无限兼容承诺。
- 动效提升反馈和体验，不代表图片生成速度由动效加速，也不代表能绕过 Photoshop 的格式或内存限制。

## 02 运行条件、界面与第一次导出

### 02.1 运行条件

按当前项目与说明，准备 Windows x64、Photoshop、可用的 Photoshop COM 注册与 `.psjs` 文件关联。导出链使用 Photoshop UXP 独立脚本，项目以 Photoshop 23.5+ 的独立脚本能力为前提；每个具体版本仍需实际确认所用 DOM、Action Manager 和历史控制 API 可用。

默认发布方式已经移除随包捆绑的 .NET 运行时，因此运行机器需另装 **.NET 10 x64 Runtime**。普通用户不需要为了运行软件安装 SDK；从源码编译的人需要 SDK。移除运行时减小的是发布包体积，不是把软件改成无需 .NET。

软件运行目录应允许当前用户写入，因为 `psx.log` 放在 EXE 同级。输出目录、系统临时目录、用户设置目录也需要可用。无需为了日常使用预先安装 Node.js；它只参与开发侧的额外脚本行为测试。

### 02.2 界面从上到下怎么看

1. 文档与连接信息：当前文档名、Photoshop 版本、画布尺寸、刷新入口。
2. 功能导航：快速导出、画板导出、图层导出、切片导出，以及设置。
3. 当前模式参数：共享输出位置和图片格式，再按模式显示图层模式、质量、存放方式或名称。
4. 任务状态：开始、进度、完成或失败原因。
5. 底部操作：打开目录、开始导出；任务期间提供停止等待。

具体启用状态取决于文档和任务状态。没有画板时不能正常使用画板导出；没有识别到有效切片时切片入口不可用；正在执行任务或刷新状态时部分操作暂时禁用。

### 02.3 第一次导出的完整步骤

1. 打开 Photoshop，再打开一份设计文档。
2. 启动 PSexp，核对顶部文档名。如果信息不对，先在 Photoshop 切到目标文档，再手动刷新。
3. 选择“快速导出”。
4. 输出位置先选“桌面”，便于找到结果；要选“文档位置”，文档必须已保存。
5. 选择 JPG 或 PNG。JPG 可先使用默认质量 80；PNG 不显示 JPG 质量行。
6. 可选填“图片名称”，例如 `方案A_预览`。不必自己加扩展名。
7. 点击“开始导出”，等待任务状态显示完成。
8. 点击“打开目录”检查实际生成文件。

这套操作用于理解工具流程。后续再根据设计组织方式使用画板、图层或切片，而不是把所有任务都套进快速导出。

### 02.4 当前文档和选择到底来自哪里

以 Photoshop 的活动文档为准。选中画板、选中图层也以 Photoshop 自己的选择为准；当前界面没有另外维护一份需要勾选的画板列表。每次开始导出会先刷新文档信息，然后生成本次参数快照。

刷新和脚本执行不是跨进程事务锁。点击导出后不要立刻切换到另一个文档或改变目标选择；否则脚本开始读取时的活动文档/选择可能已经变化。多个 Photoshop 实例同时运行的路由也没有独立选择界面。

## 03 四类导出、五条执行路径

| 界面功能 | 实际模式/字段 | 导出对象 | 常见输出 |
| --- | --- | --- | --- |
| 快速导出 | `QuickExport` | 当前文档整张画布的合成画面 | 一张当前画布预览 |
| 画板导出 / 全部画板 | `AllArtboards` | Photoshop 文档全部画板 | 各画板独立图片 |
| 画板导出 / 当前选中 | `SelectedArtboards` | Photoshop 当前选择，经原生选区导出命令处理 | 选中的画板图片；需正确选择画板 |
| 图层导出 / 一级图层 | `Layers` + `LayerExportRecursive=false` | 根层级的非背景、非排除图层或图层组 | 每个主体与有效可见公共内容合成一张完整画布图片 |
| 图层导出 / 图层 / 选中图层 | `Layers` + `true` + `LayerExportSelectedOnly=true` | Photoshop 选择的合格图层或图层组 | 每个有效选择一张完整画布图片 |
| 图层导出 / 图层 / 全部图层 | `Layers` + `true` + `LayerExportSelectedOnly=false` | 递归遍历到的合格非组图层 | 每个叶子图层一张完整画布图片 |
| 切片导出 | `Slices` | 有效原生用户切片、基于图层的图像切片 | 每个切片边界内一张裁剪图片 |

“一级”说的是层级，“选中/全部”说的是图层模式下的目标范围，“切片”说的是原生矩形区域；这三个概念不能互换。

## 04 快速导出：整张当前画布（EXP-QUICK）

### 04.1 用来做什么

把当前活动文档的整张画布保存成图片。适合发预览、看整体效果、留一个阶段性方案、快速把 Photoshop 内容交给聊天工具或文档。它不以图层边界裁剪，也不按原生切片分块。

### 04.2 怎么用、怎么命名

切到要导出的 Photoshop 文档，选“快速导出”，设置位置和格式，填写可选图片名称，然后执行。名称留空时，脚本使用去掉最后一段扩展名的文档名称；例如 `商品详情.psd` 变为 `商品详情.jpg`。填写 `商品详情_确认稿` 则由应用归并为 `商品详情_确认稿.jpg`。

图片名在快速导出里是完整文件主体，不是额外加到文档名前的前缀。格式由格式选项决定，通常不要在名称里再写 `.jpg` 或 `.png`，否则可能出现重复扩展名。

### 04.3 实现过程

1. C# 在 `%TEMP%/PSexp/<随机编号>/` 建独立临时输出目录。
2. 加载 `export/quick_export.psjs`，通过 `receipt_task.psjs` 包装任务回执。
3. UXP 在 `core.executeAsModal` 内读取 `app.activeDocument`，获得目录 Entry，调用 `doc.saveAs.png(entry, {}, true)` 或 `doc.saveAs.jpg(entry, { quality: ... }, true)`，等待保存调用完成。
4. 包装脚本枚举临时目录，报告实际生成的 PNG/JPG 文件。
5. C# 在成功后移动到最终目录，应用自定义图片名及同名策略。
6. 成功交付后尝试清理临时目录；失败则保留诊断材料。

这里 `saveAs` 的 `true` 表示按副本保存，不把活动 PSD 改成输出 JPG/PNG。它不是为每次导出额外打开一个可见 Photoshop 文档的流程。

### 04.4 注意事项与可玩的组合

- 有画板的文档使用快速导出仍是整文档保存路径。要逐画板交付，请使用画板导出。
- 当前可见性、图层效果和合成结果由 Photoshop 保存时解释；PSexp 不自己重绘 PSD。
- 不主动统一文档颜色模式、位深、元数据或 ICC 行为；不支持的保存条件由 Photoshop 报错。不要把它介绍成自动转换到所有目标规范的导出器。
- “桌面 + JPG + 自定义图片名”适合临时发送；“文档位置 + PNG”适合保留当前整体合成。
- “同名自动改名”开启时，可以反复导出得到 `_1`、`_2` 等阶段结果；这只是文件去重，不是完整版本管理系统。

源码：[快速脚本](../PSdodo/Resources/Scripts/export/quick_export.psjs)、[回执包装](../PSdodo/Resources/Scripts/export/receipt_task.psjs)、[临时输出与归并](../PSdodo/Services/ExportService.cs)。

## 05 画板导出：多页面、多规格交付（EXP-ARTBOARD）

### 05.1 全部画板与当前选中

“全部画板”适合一次交付同一 PSD 里的全套页面，例如横版海报、竖版海报、方图；“当前选中”适合只重导修改过的部分。选择发生在 Photoshop：先选中目标画板，再回到 PSexp 执行。

当前选中脚本调用 Photoshop 的 `exportSelectionAsFileTypePressed`，按宿主当前选择工作，没有按画板 ID 再筛一遍。应用会要求文档存在画板，但这不等于检查当前选中的每个对象都是画板。因此操作说明应明确“请在 Photoshop 选择画板”；误选普通图层的实际结果由 Photoshop 原生命令决定。

### 05.2 存放方式：目录策略和文件策略是两层

假设文档为 `品牌套图.psd`，上方输出位置解析为 `D:/交付`：

| 选项 | 实际行为 | 例子 |
| --- | --- | --- |
| 图片直出 | 直接放进输出根目录 | `D:/交付/横版.jpg` |
| 文档文件夹 | 以文档名创建新目录；已存在则追加目录序号 | `D:/交付/品牌套图_1/横版.jpg` |
| 覆盖文件夹 | 创建或复用文档名目录 | `D:/交付/品牌套图/横版.jpg` |

**“覆盖文件夹”只决定复用目录，不会删除整个旧文件夹，也不会自动清掉不再导出的旧图。** 文件是否覆盖仍看“同名自动改名”：开启会追加文件序号，关闭才替换同名文件。

例如使用“覆盖文件夹”但同名自动改名仍开启，第二次导出可能得到 `横版_1.jpg`；要稳定更新交付文件，需同时关闭自动改名，并自行管理本次已删除画板留下的旧图片。

### 05.3 命名、质量、实际输出

画板名称和拆分规则主要由 Photoshop 原生导出命令决定；没有通用“图片名称”输入去替换所有画板名。应在 Photoshop 中给画板起清楚的名称，尽量避免同名画板。

脚本设置 `fileType`、`quality`、`metadata: 0`、`sRGB: true`、`destFolder`、`openWindow: false`。这条路径与其他模式的 DOM `saveAs` 不完全相同，不能承诺两种路径产生逐字节相同的图片。选中画板的 PNG 命令参数固定使用 32；这个数是接口参数，不是界面上的 PNG 有损质量百分比。

### 05.4 实现过程与进度限制

两条画板路径分别加载 `all_artboards.psjs`、`selected_artboards.psjs`。全部画板使用 `exportDocumentAsFileTypePressed`，当前选中使用 `exportSelectionAsFileTypePressed`；都在模态执行中通过 `action.batchPlay` 触发。

C# 先解析最终画板目录，然后在独立临时目录执行，收集回执，再逐个移动到最终目录。原生命令负责生成，应用负责最终目录和重名处理。归并失败可能只移动成功了一部分，错误会记录当前源路径、目标路径、覆盖参数与异常信息。

包装脚本在导出命令返回后枚举文件，不是每个画板都有宿主级持续进度回调。全部画板的预期数来自探针计数，实际成功数量来自回执及磁盘文件；状态进度不能被解释为精确耗时百分比。

### 05.5 典型玩法

- 一份 PSD 放不同平台尺寸，全部画板输出，按文档自动建文件夹交付。
- 只选中客户改动的两个画板，用当前选中重导，减少不必要的重复操作。
- 用“文档文件夹”保留每次导出的整批结果；用“覆盖文件夹 + 自动改名关闭”保持交付路径稳定。二者是不同交付习惯。

## 06 图层导出：以画布为基底，按主体分别合成（EXP-LAYER）

<a id="layer-compositing"></a>
### 06.1 一级图层：完整画布上的方案合成

**一级图层导出，以整张文档画布为基底，每次选一个最外层图层或图层组作为主体，结合保留显示的公共内容，分别输出合成图片。**

一级指文档根层级：没有放在其他图层组里的图层或组。“一级”不指图层面板第一行。顶层组作为整体输出，组内子图层不拆成独立目标；真正背景和排除分支不独立导出。

可以用下面的关系理解它，但实际合成始终遵循 Photoshop 的上下叠放、遮挡、蒙版、透明度和混合关系，不能把这个关系当成无条件的数学叠加：

```text
每张输出 = 完整画布范围内，当前主体与有效可见公共内容的 Photoshop 合成结果

第一张：方案 A + 本轮公共内容
第二张：方案 B + 同一批公共内容
第三张：方案 C + 同一批公共内容
```

公共内容可以是放在上方的水印、品牌标识、边框，也可以是放在下方的底色和衬底。把不同方案做成顶层组，即可用同一套公共内容分别包装这些方案。它的玩法来自主体筛选、可见性保留和整画布保存这三条现有规则的组合。

输出尺寸沿用文档画布，不按主体的像素边界自动裁切。这里的“画布基底”指范围和坐标，并不表示自动铺白或自动创建背景。PNG 是否有透明区域仍取决于实际合成。

### 06.2 图层 → 选中图层

读取 `doc.activeLayers`，输出 Photoshop 当前选择的合格图层或图层组。选中组整体输出；同时选中了组和组内子图层时，只输出组，避免重复。排除项和真正背景仍不成为独立主体。

例如同时选中“卡片组”和其中的“标题”，不会再独立输出标题。未选中卡片组、只选标题时，会使其祖先组可见，让目标参与合成。排除项/背景保留初始可见性的规则也适用于这个模式，输出仍按文档画布。

适合从复杂文档中临时选择几项交付，不需要把它们全部调整成最外层对象。

### 06.3 图层 → 全部图层

递归进入图层组，输出合格的非组图层，也就是叶子图层；组本身不重复输出。顶层普通图层也属于候选。背景与排除分支继续跳过独立输出，并按初始可见性参与或不参与合成。

它不保留组的目录层级，文件放在同一目标目录，命名使用前缀和目标名称；不同组内同名图层可能冲突。“全部”仍受目标过滤规则约束，不能讲成 PSD 中任何对象都一定独立输出。

### 06.4 可见性角色：主体、公共内容和参考资料

| 对象 | 是否成为独立主体 | 本轮导出时的显示规则 |
| --- | --- | --- |
| 当前符合条件的一级图层/组 | 是 | 打开显示；目标组内部保留子层的初始可见状态 |
| 其他普通一级图层/组 | 轮到它时才是 | 本张先隐藏，避免其他方案混入 |
| 显示的“排除”图层/组 | 否 | 保留显示标记，可作为公共内容参与合成 |
| 隐藏的“排除”图层/组 | 否 | 保持隐藏，可存放参考和说明 |
| 显示的真正背景图层 | 否 | 保持显示，作为公共底图参与合成 |
| 隐藏的真正背景图层 | 否 | 保持隐藏，不主动打开 |

“显示/隐藏”在这里按任务开始时的快照确定。符合目标条件的普通隐藏图层仍会被打开并导出，因此不能仅靠隐藏一个普通方案来把它从一级导出名单中去掉；要跳过其独立输出，可使用排除前缀。

#### 06.4.1 “排除”前缀的准确含义

按 JavaScript 正则 `/^排除/` 判断：名称从第一个字符起为“排除”才匹配。`排除_品牌水印`、`排除说明` 都匹配；`品牌_排除`、` 排除_水印` 不匹配。排除组内的子层继承排除，不独立输出。

**排除控制是否成为独立主体；初始可见性控制是否保留参与合成的条件。** 所以同一个排除组可以存公共视觉内容，也可以存隐藏的设计参考，取决于显示状态和文档组织。

公共项建议放在最外层。排除项若放在一个普通方案组里，那个组在其他轮次被隐藏，排除项即使自身可见也不会跨越隐藏父组显示。排除组内部隐藏的子层同样不会被强制打开。

#### 06.4.2 真正的背景图层如何处理

代码判断 `layer.isBackgroundLayer`，不是判断中文名称“背景”，也不是只看是否锁定。真正背景不需要加排除前缀：原本显示就保留显示，原本隐藏就保留隐藏，始终不作为独立输出主体。

普通图层即使命名为“背景”，仍按普通层规则筛选。若转换为普通图层后 `isBackgroundLayer` 已为 false，也回到普通层规则；想继续作为公共底图，可命名为 `排除_公共背景` 并按需要显示。

关闭真正背景不保证输出一定透明，还要看是否有其他可见衬底或不透明主体；JPG 格式本身也不保留透明通道。

### 06.5 叠放顺序、尺寸与恢复边界

脚本在原文档上改变可见性，然后用 `doc.saveAs` 保存副本。没有把公共项复制到每个组里，没有重排层级，也没有自动把水印移到最上面。要覆盖主体的水印/边框应放在主体上方；底图应放在主体下方。示例树的排列顺序就是 Photoshop 从上到下的顺序。

目标组内的可见状态保留；组蒙版、图层效果、透明度、混合模式、调整与剪贴关系由 Photoshop 对本轮可见状态解释。拆开依赖图层后效果可能变化，公共项也可能被不透明主体遮住。不能承诺任意位置的排除项都会在每张图上呈现同样效果。

不会自动裁掉主体周围空白，小图标也可能得到完整画布大小的 PNG。输出是当前画布范围内的合成图，不是提取目标层原始像素文件。

任务结束在 `finally` 中从子层向父组尽力恢复原可见性，一层恢复失败不会阻止其他层恢复；错误计入任务失败。脚本没有对原文档完整历史做事务回滚，不能保证强退或宿主异常下的可见性、未保存标记及历史绝对不变。

### 06.6 文件名前缀的优先顺序

1. “文档名优先”开启：用去扩展名的文档名替代手动前缀。
2. 否则使用输入的“文件前缀”。
3. 有效前缀为空且“文档名前缀”开启：脚本退回文档名。
4. 两者都没有：只使用目标图层/组名称。

文件主体为 `[有效前缀_]目标名`。例如 `新品.psd` 的 `红色款` 默认可输出 `新品_红色款.png`；手填 `客户确认` 且文档名优先关闭，输出 `客户确认_红色款.png`；前缀留空并关闭文档名前缀，输出 `红色款.png`。

“文档名优先”主动替换，“文档名前缀”只在空值时兜底。同名覆盖或自动追加序号仍由同名策略决定。

### 06.7 完整模板示例与预计结果

```text
新品.psd                         整张画布，例如 1080 × 1080
├─ 排除_品牌水印                 显示，普通层或组，位于主体上方
├─ 排除_统一边框                 显示，边框中间留空
├─ 红色款                        顶层方案组
│  ├─ 商品                       显示
│  └─ 内部注释                   隐藏
├─ 蓝色款                        顶层方案组，原本隐藏也会作为目标
│  └─ 商品                       显示
├─ 排除_设计说明                 隐藏组
│  └─ 参考截图
└─ 背景                          Photoshop 真正背景，显示
```

选择一级图层 + PNG，使用默认文档名前缀，在无同名文件冲突且保存成功的前提下，预计得到：

| 文件 | 本轮合成内容 | 画布尺寸 |
| --- | --- | --- |
| `新品_红色款.png` | 品牌水印、统一边框、红色款的可见内容、真正背景 | 1080 × 1080 |
| `新品_蓝色款.png` | 品牌水印、统一边框、蓝色款的可见内容、真正背景 | 1080 × 1080 |

水印、边框、真正背景不各自生成文件；隐藏说明与内部注释不参与显示。若把真正背景换成普通底图，应加排除前缀并置于主体下方。这个结果按代码规则推导，不是本次实机导出的验收记录。

### 06.8 “盖印效果”应怎样解释

可以说“按每个主体分别导出盖印般的合成结果”：先切换可见性，再直接保存文档合成图片。当前代码没有在 PSD 里创建新的盖印层，没有把所有主体盖到同一张图，也没有自动生成可编辑的合并图层。

同一画布的多份完整合成，是一级模式的关键价值。各方案不必重复放一套水印和背景，就能在文档组织合适时统一复用公共内容。

### 06.9 一级模式的组合玩法

以下都是现有规则组合出的工作方法，需用户准备文档后执行，不是另外实现了一个模板引擎或自动生成器。

| 玩法 | 文档怎么组织 | 预计用途与边界 |
| --- | --- | --- |
| 批量加品牌水印 | 顶层可见 `排除_水印` 放上方；每个方案一个普通顶层组 | 每个方案带同一水印；水印仍受透明度、遮挡和父级影响 |
| 批量套统一边框 | 可见排除边框组放上方，中间透明；主体位置按画布统一 | 输出统一包装；没有自动缩放或居中主体 |
| 多款商品统一底图 | 真正背景或下方可见排除底图；每款商品一个顶层组 | 共用场景/底色分别输出；差异化商品阴影可放各自方案组 |
| 统一品牌模板出多份内容 | 公共标识和固定装饰放排除组，变动文案/图片分别放方案组 | 一次输出各份设计；文字与图片需事先准备，不会自动从表格填充 |
| 同坐标整画布资源 | 多个主体按统一画布坐标摆放，隐藏背景和其他不需要的公共衬底，输出 PNG | 保持相同画布与对齐位置，便于外部叠合；不自动裁边 |
| 比较不同方案 | A/B/C 分别顶层组，公共外框/底图保持一致 | 减少手动逐组显隐和保存；隐藏普通组仍会被轮到 |
| 留存参考但不交付 | 把参考和设计说明放隐藏排除组 | 不独立输出，也不参与可见合成；可见排除项不适合存必须隐藏的说明 |
| 分两轮导出带水印/无水印 | 第一轮水印排除组显示，第二轮隐藏；改目录或使用合适重名策略 | 两次手动执行得到两套图，不会一次自动生成所有组合 |

进一步可分轮切换不同公共底色或公共包装，给同一批主体生成不同交付版本。每轮只使用这一轮开始时的公共可见状态，代码不自动做“所有主体 × 所有背景”的笛卡尔积组合；需要提前组织完整方案，或由用户手动切换公共内容再执行。

### 06.10 源码依据、执行过程与验证范围

当前服务通过 `ExportLayersAsync` → `ExportLayerBatchAsync(sliceMode: false)` 调用 `export/layer_batch`，并注入 `RECURSIVE`、`SELECTED_ONLY`。一级模式为 `RECURSIVE=false`，不是运行历史 `layers.jsx`。

| 结论 | 实际代码依据 |
| --- | --- |
| 只把根层级作为一级主体 | `!recursive ? node.parents.length === 0 : ...` |
| 排除项与真正背景不独立导出 | `!node.blocked && !node.layer.isBackgroundLayer` |
| 排除组的子层继承规则 | `blocked = excluded \|\| /^排除/.test(layer.name)`，递归传入 `blocked` |
| 原始显示/隐藏有区别 | `visibility = new Map(... layer.visible)` 保存初始值 |
| 当前主体及其祖先打开 | `layer.id === target.id \|\| targetNode.parents.includes(layer.id)` |
| 排除项、背景、目标组子层保留初始可见标记 | `(node.blocked \|\| layer.isBackgroundLayer \|\| node.parents.includes(target.id)) && visibility.get(layer.id)` |
| 其他普通层不混入本轮 | 上述显示条件都不成立时，赋值 `visible=false` |
| 整文档合成保存为副本 | `doc.saveAs.png(entry, {}, true)` 或 `doc.saveAs.jpg(..., true)`；没有裁边、重排或创建盖印层的步骤 |
| 结束后尽力恢复 | `finally` 中逐层恢复 `visibility.get(layer.id)` |

主要源码：[服务选择与注入](../PSdodo/Services/ExportService.cs) 的 `ExportLayersAsync/ExportLayerBatchAsync`、[实际图层脚本](../PSdodo/Resources/Scripts/export/layer_batch.psjs) 的 `visit/targets/exportBatch`、[界面参数快照](../PSdodo/ViewModels/MainViewModel.cs) 的 `Snapshot/ResolveLayerImageName`。

现有 [脚本行为测试源码](../tests/PSdodo.Tests/uxp-layer-batch.test.cjs) 中，`top-level exports include hidden targets and skip excluded targets` 等用例明确断言：隐藏的普通目标会输出，可见的排除覆盖层与背景保留在各次保存的可见集合中。它们模拟 DOM，没有真实渲染 Photoshop 的水印、蒙版或混合效果；不能把这些断言当成所有玩法已实机通过。本轮只核对源码，没有运行测试。

每张保存完成即写进度，最终恢复可见性后写完成回执。已经写出的图片在中途失败时保留。同名覆盖会对最终文件路径去重计数，因此完成文件数不一定等于处理的主体数。

## 07 切片导出：按 Photoshop 原生切片分块（EXP-SLICE）

### 07.1 这里的切片是什么

读取 Photoshop 文档本身的切片元数据，以原生用户切片和基于图层生成的切片为对象，按各矩形边界输出当前合成画面。适合电商长图分块、按参考线组织的图片模块、已经用切片工具划分的交付区域。

普通图层、画板、参考线本身不是切片。先在 Photoshop 用切片工具创建用户切片，或使用相应的基于参考线新建切片操作，再回 PSexp 刷新识别。仅画参考线而没有创建实际切片不会变成可导出目标。

### 07.2 与“存储为 Web 所用格式”的关系

相同点是利用 Photoshop 的原生用户切片范围。不同点是 PSexp 按边界自行裁剪并保存 JPG/PNG，而不是完整调用旧 Web 导出对话框。

| 项目 | 当前行为 |
| --- | --- |
| 用户生成的图像切片 | 导出 |
| 基于图层生成的有效图像切片 | 导出 |
| 自动补齐空隙的切片 | 跳过 |
| 非图像切片 | 跳过 |
| 零宽/零高或缺少边界的切片 | 跳过 |
| JPG/PNG 与质量 | 使用 PSexp 本次统一参数 |
| Photoshop 中逐片设置的不同优化格式、质量 | 不读取并复用 |
| HTML、链接、表格布局 | 不生成 |
| 只输出部分已选切片 | 当前没有对应范围选择器；输出全部合格切片 |

### 07.3 使用步骤与排序命名

1. 在 Photoshop 划好实际切片，核对边界、切片名称和当前可见画面。
2. 回 PSexp 刷新，选择“切片导出”。
3. 选输出位置、格式；JPG 可调质量。
4. 填“文件前缀”，例如 `商品详情`，不能留空。
5. 执行后检查输出，特别是长图的首尾、接缝和顺序。

脚本按 `top` 从小到大、再按 `left` 从小到大、最后按 `sliceID` 排序。它是坐标数值排序，不会先把高度接近的切片智能聚成行，也不是按名称或手工编号排序。

命名为 `前缀_切片名.扩展名`；切片没有名称则用排序后序号，最少两位，例如 `商品详情_01.jpg`、`商品详情_02.jpg`。有名称 `顶部卖点` 则输出 `商品详情_顶部卖点.jpg`。同名问题仍由自动改名选项处理。

### 07.4 为什么还会出现一个临时文档

源文档要保持完整，所以脚本复制一个合成副本，在副本上裁剪。当前实现已经改成**整批只创建一个副本并重复使用**，不是每一片开关一次文档：

1. 通过 Action Manager 读取文档 `slices` 属性并筛选、排序。
2. 调用 `source.duplicate("PSexp slices", true)`，建立一个合成临时文档。
3. 若宿主提供 `registerAutoCloseDocument`，注册自动关闭。
4. 每片调用 `suspendHistory` 保存本轮状态。
5. 按切片原始边界 `crop`，调用 `saveAs` 写图片。
6. 调用 `resumeHistory(suspension, false)` 回滚副本文档改动，回到完整画布。已写到磁盘的图片保留。
7. 下一片前校验副本宽高已恢复，防止累计裁剪造成错位。
8. 任务结束由宿主关闭副本；无自动关闭接口的兼容路径显式 `closeWithoutSaving()`。尽力切回源文档。

这个副本是保护源文档并执行裁剪的工作空间，出现一次是当前设计。它仍可能在 Photoshop 文档标签中短暂出现；“优化反复开启”不等于“完全没有临时文档”。

### 07.5 超过 30000 像素的画布能怎么理解

该实现没有把整图先交给旧 Web 导出器，也不会为了导出擅自缩小整张画布。因此，对某些整体超长、但单片尺寸能保存的设计，可以逐片输出，这是这条实现路线的价值。

不要把它宣传成“任何尺寸都能导出”或“解除 Photoshop 所有限制”。整个源文档仍需可打开和复制，单片仍受 JPG/PNG 保存能力、颜色模式、位深、内存、磁盘和宿主 API 支持约束。超长文档的实际可行性应由用户文件验证。

### 07.6 常见误解

- 多个普通图层不会自动变成多个切片；图层导出和切片导出是两套目标规则。
- 同一切片区域输出的是当前完整合成，不是只取与该矩形同名的图层。
- 原生切片名影响输出名称，不代表读取该切片的 Web 优化预设。
- 部分切片写出后失败，已经生成的图片保留；不能以“目录里有几张图”判定整批成功。
- PSexp 的停止等待不会强制 Photoshop 取消；宿主是否进入取消状态，脚本依 `context.isCancelled` 和宿主清理 API 处理。

## 08 通用参数：输出位置、格式、质量与命名

### 08.1 输出位置（PARAM-DESTINATION）

| 预设 | 解析规则 | 使用场景 | 需要注意 |
| --- | --- | --- | --- |
| 文档位置 | 当前文档探针返回的 `doc.path.fsName`，即文档所在目录 | 图片随项目保存 | 未保存文档没有有效目录，不会悄悄改用其他位置 |
| 桌面 | Windows `SpecialFolder.DesktopDirectory` 返回的实际桌面 | 临时预览和快速交付 | 桌面若被重定向到 OneDrive，图片也会进入那个实际目录 |
| 自定义 | 当前输入路径去除首尾空白 | 固定交付目录、共享目录 | 必须是完整路径且有写权限，可手填或通过文件夹按钮选择 |

只有“自定义”展开输入框。切回文档位置或桌面，不会覆盖记住的自定义路径；预设下面显示实际解析的位置。画板的文档文件夹策略在这个根目录上继续生效。

应用在执行前要求完整路径，调用 `Path.GetFullPath` 规范化，创建目录，并使用随机 `.psx-write-<编号>.tmp` 文件尝试写入，关闭时删除，以便在启动 Photoshop 任务前发现明显权限问题。这个预检不能保证 UXP 对网络盘、特殊路径或被安全软件拦截的目录一定可访问，两边运行环境仍可能不同。

切换当前预设本身不等于保存为下次启动的默认值。需要在“设置 → 导出”点击“将当前参数设为默认”。通过浏览按钮选目录时，应用切到自定义位置。

### 08.2 JPG 与 PNG（PARAM-FORMAT）

JPG 适合常见照片、预览和对体积敏感的交付，格式本身不保留透明通道；PNG 适合需要保留透明或无损像素压缩的输出。PSexp 不提供单独的透明开关、背景铺白选项、DPI/分辨率重采样器或尺寸缩放器。输出内容与透明效果还受源文档、可见公共背景及 Photoshop 保存条件影响。

选择 PNG 后隐藏 JPG 质量行，不代表把当前质量清零；切回 JPG 可继续调节。不同导出模式走的 Photoshop 命令不同，不能把某条命令的 sRGB/元数据设置推广到所有模式。

### 08.3 图片质量与滚轮（PARAM-QUALITY）

界面允许 **1–100，步长 1**，默认 80。质量条有 25 个视觉刻度，对应 4、8、12…100；拖动时实际按指针横向比例取整，可以得到刻度之间的整数值。也可在右侧数值框输入。

- 点击或拖动质量条：即时更新数值，产生短暂反馈。
- 在图片质量区域滚轮：纵向上滚增加、下滚减少；普通一格通常一步。
- 触控板的小增量先累积；反向或间隔超过 400ms 会清余量。单次合并事件最多执行 4 步，离开区域重置累计。
- 质量输入框正在编辑时，滚轮先结束编辑，再应用最终滚轮值，减少失焦时旧文本覆盖新值的情况。
- 分段式按钮、模式切换不接受滚轮切换；滚动页面不会顺便改 JPG/PNG、主题、模式等选项。

DOM 保存 JPG 的三条路径——快速、图层、切片——将界面值映射为 `Math.round(12 * quality / 100)`，即 Photoshop 的 0–12 档。因此界面相邻的质量值可能映射到同一保存档，80 会映射为 10。画板导出把 JPG 质量传给原生命令，不能假设映射完全一样。

PNG 路径没有 JPG 有损质量百分比；`ResolveScriptQuality` 或画板脚本里的 32 是接口用途参数。图层/切片虽然注入当前质量，但 PNG `saveAs.png(entry, {}, true)` 并不使用这个值作为有损质量。

源码：[质量与滚轮交互](../PSdodo/Views/MainWindow.axaml.cs)、[滚轮累积](../PSdodo/Controls/WheelStepAccumulator.cs)、[参数校验](../PSdodo/Services/ExportSettingsValidator.cs)。

### 08.4 自动改名与覆盖（PARAM-RENAME）

设置“同名自动改名”默认开启：有同名目标时追加 `_1`、`_2` 等数字，保留旧文件。关闭时允许覆盖同名输出。

快速/画板最终归并由 C# 检查目标文件；图层/切片由 UXP 先枚举已有名称，并在本轮成功写入后更新集合。JS 名称集合按小写比较，避免大小写造成重复判断偏差。

如果两个图层或切片的清理后名称相同，关闭自动改名时，后一个可能覆盖前一个。同一目录中的同名冲突不只发生在“重新导出一次”，一轮任务内部也可能发生。

脚本会把常见 Windows 非法字符、控制字符替换为下划线，去除尾部句点和空格；C# 快速命名、画板目录也有文件主体清理。它们并不是完整的文件系统兼容性保证：超长路径、系统保留名、权限、锁定、外部并发写入仍可能报错。应给文档、画板、图层、切片起简短且可区分的名称。

### 08.5 哪些名称输入在哪个模式生效

| 字段/来源 | 快速 | 画板 | 图层 | 切片 |
| --- | --- | --- | --- | --- |
| “图片名称”输入 `ImageName` | 完整文件主体，可留空 | 不显示、不作为通用画板名 | 同一输入位置显示为“文件前缀” | 不使用 |
| 文档名称 `DocumentName` | 默认保存名来源 | 文档子目录来源 | 可作默认或优先前缀 | 不自动替代切片前缀 |
| “文件前缀” `FileName` | 不使用 | 不使用 | 不使用这个字段 | 必填，默认 `export` |
| 对象名称 | 默认文档名 | Photoshop 画板名 | 图层/组名 | 切片名或排序序号 |

源码中部分旧注释把名称写成“通用前缀”，介绍行为时应以 `Snapshot()`、`ResolveLayerImageName()` 和实际脚本为准。

<a id="tasks"></a>
## 09 任务执行、状态、取消与部分成功（TASK）

### 09.1 什么时候能开始

`CanExport` 要求：没有忙任务、没有正在刷新，Photoshop 进程存在、桥接条件可用、活动文档存在、输出位置有效。画板模式另需文档有画板；切片模式另需切片探测为真且文件前缀非空。最终仍会做目录写入预检。

桥接“可用”标志在当前 Windows 实现主要表示平台支持，并不是对 Photoshop COM 注册和每条 API 的完整健康检查。看到 Photoshop 正在运行，也不能据此保证独立脚本关联正确。

### 09.2 一次任务的阶段

```text
点击开始
  → 刷新当前文档
  → 生成本次 ExportSettings 参数快照
  → 检查输出位置、质量、写权限
  → 根据模式选择脚本并注入参数
  → 写临时 .psjs，通过 Windows 文件关联交给 Photoshop
  → 轮询 result.json，核对真实文件
  → 快速/画板执行最终文件归并
  → 显示完成或错误，成功时可打开实际目录
```

任务开始后启用忙状态，锁定相关切换，清空本轮文件进度。任务状态包含任务名、生成数、最近文件以及错误文本。等待期间显示不确定进度条；“已生成 X / N”是数量进度，不是图片处理百分比。

内部 `ExportedFiles` 最多保留 200 条、UI 日志集合最多 500 条，避免内存无限增长；当前主界面以任务状态卡为用户反馈，没有把这些内部集合都呈现为完整历史管理界面。

### 09.3 成功判定不是“脚本已启动”

Windows 成功打开 `.psjs` 只表示任务已派发。应用还要等脚本写明确的 `done`、`success`、`files`，并确认报告的图片文件真实存在，才判定完成。

回执默认每 250ms 读取一次。首次回执超过 30 秒未出现会失败；有回执后，整个默认等待上限是 30 分钟。时间是当前实现常量，不是界面可调项。读到写了一半的 JSON 会重试，而不是立刻当作最终损坏。

### 09.4 “停止等待”的真实含义

应用取消的是自己的等待令牌，**没有可靠地向已经启动的 Photoshop 模态任务发送强制终止命令**。所以状态会写“已停止等待”，而不是宣称“Photoshop 已中止所有导出”。

停止后，Photoshop 可能还在裁剪、保存或恢复可见性。先回 Photoshop 确认任务结束，再重新导出；不要立刻清掉临时脚本、任务目录或与其竞争修改文档。因为应用侧忙状态结束，并不证明宿主侧已经释放。

### 09.5 部分生成不等于完整成功

图层/切片逐张写图片，中途失败不会删除已经生成的文件；画板归并也可能只移动一部分。失败时应看任务状态和日志，再检查当前目录及临时目录。没有整批原子提交、自动撤销全部磁盘输出或自动续传能力。

“打开目录”成功后优先打开最近一次成功结果所在的实际目录，例如画板子文件夹；本轮失败不保证自动定位所有部分结果。导出结束会尝试激活已有主窗口以便查看状态，这不等于保证操作系统在所有前台策略下都允许抢焦点，也不代表托盘隐藏窗口一定自动显示。

源码：[命令与忙状态](../PSdodo/ViewModels/MainViewModel.cs)、[回执监视](../PSdodo/Core/PsConnection/UxpTaskWatcher.cs)。

## 10 设置：四类卡片与保存规则（SETTINGS）

设置按“常规、导出、联动、更新”组织。类别导航、标题和卡片按实际内容宽度对齐，长内容由设置区滚动；底部状态显示自动保存结果。所有真正“关闭/开启”的分段开关，左侧为关闭、右侧为开启。

### 10.1 常规 → 界面

| 项目 | 选项/默认 | 用途 |
| --- | --- | --- |
| 主题 | 跟随系统 / 浅色 / 深色；首次默认浅色 | 按环境与偏好切换语义颜色 |
| 空白处拖窗 | 关闭 / 开启；默认开启 | 通过窗口空白区域移动工具，保留按钮、文本编辑、滚动条、质量条自身操作 |
| 质量条悬停动效 | 关闭 / 开启；默认开启 | 仅控制刻度悬停放大，点击和数值变化反馈仍保留 |

主题切换修改颜色资源，不改布局尺寸。设置页没有整页再包一层白色大卡片，而由各功能卡片承担层次；深浅模式分别配置卡片、轨道、选中块和边框颜色。

### 10.2 常规 → 窗口

| 项目 | 选项/默认 | 用途 |
| --- | --- | --- |
| 关闭后常驻 | 默认开启 | 关闭按钮改为隐藏到托盘，程序与后台任务继续运行 |
| 窗口置顶 | 默认关闭 | 让普通主窗口保持在其他窗口前方；导出与收纳态有额外规则 |
| 贴边收纳 | 默认开启 | 拖到屏幕外边缘，变成半露出的图标入口 |
| 收回等待 | 快速 250ms / 标准 420ms / 从容 800ms；默认标准 | 收纳窗口展开后，鼠标离开到自动收回前的等待 |

收回等待不改变神灯动画的播放时长。关闭贴边收纳与关闭后常驻是两种独立偏好，不应合并成一个“隐藏”功能来解释。

### 10.3 导出 → 文件命名与默认导出参数

文件命名包含同名自动改名、文档名前缀、文档名优先，细则见第 06、08 节。它们属于行为偏好，修改自动保存。

“将当前参数设为默认”保存当前输出位置预设、自定义路径、图片格式与质量，并一并写入其他持久偏好。下次启动加载保存的默认值。日常临时改格式、质量、路径不立即替换这些默认值，避免为发一张临时预览改变常用参数。

不会由这个按钮完整保存每个界面状态：快速图片名、切片前缀、当前导出大模式、画板存放方式、设置类别、任务历史都没有作为相应当前值写进 `AppSettings`。启动默认回快速导出，切片前缀回 `export`，画板存放方式回图片直出。

### 10.4 联动 → Photoshop

“自动同步文档”默认开启，共用一个偏好控制：主窗口回前台时的自动刷新，以及 Photoshop 在前台时的文档身份轻量检查。检查间隔为 0.8 / 1.2 / 2 秒，默认 1.2 秒。

轻量探针返回当前文档的 ID 与名字；检测到身份变化后再读取完整信息，减少每轮都扫描画板和切片的开销。导出、正在刷新、重复检查或 Photoshop 非前台时跳过。收起到托盘会停止主窗口的文档检查计时器，恢复窗口再继续。

它主要跟踪文档切换，不是文档内容的完整实时观察器。同一文档里新增切片、修改画板、另存路径但身份未变时，可能需要手动刷新或回前台触发完整探测；不能把 1.2 秒讲成“任何编辑都在 1.2 秒内同步”。

### 10.5 联动 → 数据与日志

两条独立入口，每条左侧名称和说明、右侧“打开文件夹”：

- 设置目录：用户偏好和默认参数，默认 `%APPDATA%/PsExporter/`。
- 日志目录：EXE 所在目录，核心文件 `psx.log`。

悬停提示可看实际路径。按钮只打开目录，不会清理、上传或重置这些文件。它们不是输出图片目录。

### 10.6 更新 → 自动更新与版本信息

自动检测、后台下载均默认开启。版本卡显示当前程序集版本、检查/下载/安装状态、更新说明、进度及对应动作。发现新版本时设置入口提供提示，进入设置可转到更新类别。详见第 13 节。

### 10.7 自动保存失败怎么办

偏好更改后调用 `SettingsService.Save()`，写临时 JSON 再替换正式设置。失败会显示保存错误并记日志；不是每次 UI 改变都能保证磁盘已经成功落盘。

源码：[设置布局](../PSdodo/Views/MainWindow.axaml)、[设置状态](../PSdodo/ViewModels/MainViewModel.Settings.cs)、[配置保存](../PSdodo/Services/SettingsService.cs)。

## 11 窗口、托盘、收纳与位置恢复

### 11.1 尺寸、阴影、拖动与失焦（WINDOW-BASIC）

常规默认尺寸 440 × 660 DIP，最小目标 360 × 600 DIP；实际受当前屏幕工作区约束。DIP 是跟随 DPI 缩放的逻辑单位，不是所有显示器都相同的物理像素。宽高独立保存；虽然模型保留了比例常量，不应宣传为固定比例窗口。

标题栏还提供手动刷新、图钉置顶、设置、最小化和关闭。最小化与托盘隐藏不同；设置按钮在导出忙时不可用，刷新也避免在导出期间重入。图钉和设置里的置顶操作修改同一偏好。实际置顶状态为“用户置顶或正在导出或正在边缘收纳”，因此用户偏好关闭时，导出期间仍会临时置顶，任务结束恢复相应状态。

主窗使用连续曲率外形和柔和阴影；阴影需要透明外边距，截图动画也要保留同一坐标体系。边缘保留调整大小的命中区域。空白处拖动不应抢按钮、输入框、滚动条和质量条的操作。

输入框在点击外部、页面切换、窗口失活时结束当前编辑，让光标和焦点状态自然退出。输入控件仍保持正常可编辑和键盘焦点语义，不是永久禁止焦点。

### 11.2 四边贴边收纳（WINDOW-DOCK）

开启后，把普通窗口拖到屏幕外边缘附近，结束拖动时评估收纳。当前入口默认热区为 48 DIP，支持左、右、上、下边缘。多屏相邻的共享边不作为外边缘收纳点，避免在跨屏拖窗时误收纳。

收纳后，完整主窗口让出工作区域，留下沿边缘半露出的软件图标。当前视觉图标基准约 56 DIP，约一半在边缘外，周围增加透明触发范围以便操作。图标窗独立置顶，不等于普通主窗口的用户置顶偏好。

鼠标悬停或点击入口可展开；移开后等待设定延时再收回。展开状态周围有约 24 DIP 的指针容差，减少从窗口边缘经过时立刻收回。通过拖窗或托盘/重复启动的显式激活可回到普通窗口状态。

收纳、展开、退出收纳是不同阶段，相关代码有动画代次和状态保护，以避免快速连续操作时旧帧覆盖新状态。重启直接恢复收纳态时不必先播放一次完整窗口再缩回。

### 11.3 托盘常驻和右键菜单（WINDOW-TRAY）

“关闭后常驻”开启且托盘初始化成功时，点关闭按钮隐藏主窗口。程序没退出，导出和自动更新检查仍可继续；主窗口的文档同步、状态动画、边缘悬停计时器会停下以减少无用活动。

单击系统托盘图标恢复主窗口，右键菜单如下：

| 菜单项 | 行为与启用条件 |
| --- | --- |
| 显示主窗口 | 从隐藏/收纳/最小化状态恢复并激活 |
| 快速导出当前画布 | 切到快速导出，使用当前公共参数发起新任务并恢复窗口；要求就绪、无忙任务 |
| 打开输出目录 | 打开最近成功输出位置；通常成功导出后启用 |
| 打开日志目录 | 打开 EXE 同级目录 |
| 窗口置顶 | 切换主窗口置顶；勾选状态与主界面联动 |
| 设置 | 显示主窗口的设置页 |
| 检查更新 | 进入更新页并发起检查；更新操作忙时不可重复检查 |
| 退出 PSexp | 真正结束程序；导出忙时禁用，请先完成或停止等待 |

托盘“快速导出”使用的是当前输出位置、格式、质量和快速图片名称等状态，不是另外一套固定导出模板，也不是无论 Photoshop 状态如何都能后台强制执行。隐藏期间文档缓存可能较旧，实际执行前仍会刷新。

关闭后常驻不等于开机启动，也不等于贴边收纳。关闭后常驻关闭时，窗口正常关闭即退出；托盘初始化失败时也回到正常关闭行为。系统关机、程序更新发起的退出不应被拦截成“再藏进托盘”。

### 11.4 单实例与重复双击（WINDOW-INSTANCE）

同一 Windows 会话内使用 `Local\PSexpV3` 对应的命名互斥体和激活事件协调单实例。重复启动时，新进程向主实例发激活信号后退出，原主窗口恢复。

这使用户在托盘找不到窗口时可以再双击 EXE 找回已有实例。不要介绍为支持同时启动多个独立导出窗口，也不要保证跨 Windows 登录会话互相激活。

### 11.5 重启恢复位置、尺寸和收纳状态（WINDOW-RESTORE）

当前源码保存正常展开位置 X/Y、尺寸、屏幕工作区、缩放、是否收纳以及收纳方向。移动/调整后经防抖保存，关闭或收起托盘前也会保存。

- 正常窗口退出再启动：恢复上次位置和尺寸。
- 上次是贴边收纳：恢复对应边缘入口和收纳状态，而不是先露出整窗再收回。
- 恢复时屏幕工作区或 DPI 改变：按原相对位置映射到新可用范围，并约束可见性。
- 上次屏幕已移除、坐标不可访问：选择可用屏幕并纠正位置；出错尽力回到可见普通窗口，记录警告。
- 上次边缘因多屏关系变化不再是外边缘，或贴边收纳已关闭：不强行恢复无效收纳。

保存的是展开参考坐标，不是动画期间将真实主窗口暂存到的 `(-32000, -32000)`。托盘隐藏造成的临时状态清理也不应覆盖已保存的贴边位置。

这个恢复范围不包含“重新启动后自动保持托盘完全隐藏”、最小化状态、上一任务继续运行、上次当前页面或临时输入。窗口几何恢复与任务恢复不是一回事。崩溃或断电也只能恢复最后一次成功写入的状态。

## 12 动效与连续曲率设计（UI-MOTION）

### 12.1 动效是怎样服务操作的

PSexp 的特点之一是高频操作有明确反馈：分段块滑向新选项，质量变化轻微回弹，连接和刷新有状态提示，贴边收纳把窗口形态变成入口。动效主要发生在绘制层，避免为“看起来动一下”反复改变布局尺寸或点击热区。

### 12.2 分段式按钮

共享控件 `AnimatedSegmentTrack` 保留内部 `Button.Command` 作为业务入口；选中块由绘制层跟随 `SelectionValue` 移动，约 240ms，带轻微超调与压缩反馈。快速连点从当前绘制位置继续转向，不把动作排队播放。

只通过点击或正常按钮键盘操作切换，**不响应滚轮改选项**。所有开关关闭在左、开启在右；语义不是开关的选项，如“一级图层/图层”“选中图层/全部图层”，按内容逻辑排序。

设置项二段轨道常用 112 DIP，三段轨道用 168 DIP，保持一行、右边缘对齐，给三段文字足够空间。不能为了外框完全等宽把“跟随系统”等文案截短或强制挤压。

### 12.3 质量条反馈

悬停刻度可轻微放大，热区不变；选中项不会因为当前质量长期保持放大。点击或数值变化触发约 180ms 的短反馈，结束回到 1 倍，脉冲缩放上限约 1.12。“质量条悬停动效”关闭只移除悬停放大，不移除数值变化提示。

### 12.4 神灯收纳的原理

不是只移动一个矩形窗口。应用先捕获自身界面为纹理，用独立透明 `GenieAnimationWindow` 承载 `GenieMeshControl`：

1. 将矩形纹理划分成默认 16 × 16 网格，即 17 × 17 个顶点。
2. `EdgeSnapHelper.CalculateGenieMeshData()` 根据方向和收纳进度改变顶点坐标，靠近目标边缘的区域更早收缩，形成非线性漏斗与脊线偏移。
3. 保留纹理坐标，将原窗口图像贴到变形后的三角形网格。
4. Skia `DrawVertices` 绘制逐帧结果。
5. 动画窗口覆盖真实主窗口交接，结束后停放/复用承载窗口和纹理，切到图标或可交互主窗口。

常规收回约 280ms、展开约 260ms，另有鼠标离开后的等待。这里是二维纹理网格产生的神灯视觉，不是操作系统原生 macOS 动画，也不应把源码注释中的“3D”讲成完整三维场景引擎。

性能处理包括纹理和网格拓扑复用、静态收纳快照缓存、引用计数保护绘制线程资源、无效动画代次丢弃，以及停下静止状态的不必要轮询。窗口任务栏/Alt+Tab 属性修改尽量在遮挡或透明状态交接，以降低显隐闪烁。

收纳入口另外通过 `DockDesktopIntegration` 注册 Shell 工具窗身份并处理显示桌面、任务栏重建和层级变化，活动时有约 1 秒的置顶守护。它不预留一整条屏幕工作区，也不接管全局快捷键。因此“停掉不必要轮询”不等于软件所有后台计时器都为零；这里有专门保证入口可找回的守护逻辑。

### 12.5 其他反馈

- Photoshop 已连接状态使用周期约 1600ms 的轻微透明度/缩放呼吸。
- 手动刷新状态有旋转及约 140ms 收尾，反映正在刷新而不是重新打开软件。
- 设置类别内容约 170ms 淡入，快速切换会从当前透明度重新衔接。
- 托盘菜单使用统一的连续曲率背景、菜单项悬停与出现反馈，不是额外启动一个设置窗口。
- 当前没有统一“关闭所有动效/减少动态效果”用户开关，不能把质量悬停选项说成全局无动画模式。

### 12.6 连续曲率 R 角是什么

`ContinuousCorners` 每个角用两段三次贝塞尔曲线构造：与直边衔接处曲率为零，转角中点保持切线和曲率连续，称 G2 连续。填色、描边和裁剪共用轮廓；尺寸、半径、线宽不变时复用几何，减少重复构造。

它控制的是转角轮廓与一致性，不是把普通圆弧简单缩放。主要共享容器、按钮绘制层和分段指示块采用这套逻辑；不能据此断言每个 Windows 系统元素都被替换为自绘。

源码：[分段轨道](../PSdodo/Controls/AnimatedSegmentTrack.cs)、[连续曲率](../PSdodo/Controls/ContinuousBorder.cs)、[神灯网格](../PSdodo/Controls/GenieMeshControl.cs)、[变形计算](../PSdodo/Services/EdgeSnapHelper.cs)、[设置淡入](../PSdodo/Views/MainWindow.Settings.cs)、[设计规范](UI规范.md)。

## 13 检测更新、后台下载与重启安装（UPDATE）

### 13.1 用户操作与时间

自动检测开启时，启动约 3 秒后检查一次，此后循环约每 6 小时检查。它不是每次 Photoshop 导出后检查。也可在设置更新页或托盘菜单手动检查。

发现较新版本后显示更新说明。如果开启后台下载且当前为可安装的单文件版，会下载并校验，随后提示“重启并更新”。后台下载不会自行决定立刻退出程序安装。

未下载时按钮显示“下载并更新”；用户点击这个动作会在下载和校验后继续启动安装，并不一定再弹出第二次确认框。已下载时点击“重启并更新”安装。导出忙时禁止安装；下载完成后也会再次检查忙状态。

关闭自动检测只停止定时检查，不等于关闭手动检查；关闭后台下载仍可发现版本，由用户手动触发下载更新。当前没有独立的下载暂停/续传/取消按钮，退出会取消应用生命周期内的网络等待。

### 13.2 版本号、GitHub 和服务器是三件事

自动更新比较程序集版本与清单 `version`，只把严格更大的版本视为新版。替换同版本 EXE、修改源码或推送 Git，都不会自动让旧客户端认为出现新版本。

版本检查地址在源码中固定为 `https://yusnip.top/psexp/version.json`。它是当前客户端更新源配置，不代表本文已经联网确认此刻服务在线或包内容一致。GitHub Releases 是另一个分发入口；两边需要发布流程协调，客户端不会自动拿 Releases 里的任意最新附件替代服务器清单。

维护者应每次正式发布递增版本，生成对应 EXE，完成发布与上传，再发布指向已经可下载文件的清单。先推清单、后慢慢传包会导致客户端下载失败。

### 13.3 下载与校验规则

| 检查项 | 当前规则 |
| --- | --- |
| 清单请求 | HTTPS，带时间戳与 NoCache；请求独立超时约 15 秒 |
| 清单大小 | 最多 128 KiB |
| 软件标识 | `name` 必须为 `PSexp` |
| 版本 | 可解析，至少包含 major/minor/build 三段 |
| 下载地址 | HTTPS、主机 `yusnip.top`、默认端口、无用户信息、路径以 `/psexp/` 开头 |
| 重定向 | 不自动跟随 |
| 更新包大小 | 正数且最多 512 MiB；声明长度、实际流长度与清单要一致 |
| 发布身份 | 内嵌公钥验证 `signed_update`；无有效签名即拒绝 |
| 文件完整性 | SHA256 必须与已验签清单匹配 |
| 内置版本 | 下载 EXE 的 major/minor/build 与清单一致 |
| 下载时限 | 独立上限约 10 分钟 |

当前源码先以内嵌固定公钥验证更新清单签名，再使用认证过的下载地址、大小、SHA256、版本等字段。缺签、坏签、未知密钥全部拒绝，不回退无签名更新；平铺字段只照顾旧客户端，新客户端只读取已验签 payload。签名使用 RSA-3072/SHA256/PKCS#1 v1.5。它是元数据签名，没有对 EXE 做 Windows Authenticode 代码签名；不能因此保证服务器或软件零风险。客户端保护需编译进新 EXE，旧包不会因服务器补签自动获得验签能力。完整协议、私钥保管和首次升级见 [更新安全与发布签名](更新安全与发布签名.md)。

### 13.4 下载位置与安装机制

更新缓存位于 `%LOCALAPPDATA%/PsExporter/updates/<随机编号>/`，内含下载的 `PSexp.exe`。安装时在同一缓存目录生成 `install.ps1` 与 `install.json`。PowerShell 脚本文本定义在 `UpdateService.cs`，不是一份需要用户自己准备的仓库外脚本。

安装步骤：

1. 客户端以验签后生成的不可变清单确认当前安装形式、必要运行时和待安装文件。
2. 写入安装脚本及参数：源 EXE、目标 EXE、期望哈希、当前进程 PID、日志路径。
3. 隐藏启动 Windows PowerShell 安装辅助程序，应用正常请求退出。
4. 安装程序最多等待旧进程退出 45 秒，不是直接强杀 Photoshop。
5. 再次核对下载文件 SHA256，将其复制到目标旁的随机 `.new` 文件并再次校验。
6. 使用 `File.Replace` 替换当前 EXE，同时生成随机 `.bak` 备份；替换失败按当前实现最多重试 30 次，间隔 500ms。
7. 写入 EXE 同级日志，正常显示新程序。
8. 异常时写失败日志；已经替换过则尝试用备份回滚，再尝试启动目标程序。

备份是失败回滚材料，没有用户界面上的任意历史版本选择器。缓存和备份没有完整的自动轮换清理机制；清理应在确认安装结束后进行。

### 13.5 安装形式和边界

自动安装当前只适用于发布的单文件 EXE。若应用目录存在 `PSexpV3.dll`，或通过 `dotnet.exe` 运行，按目录开发版处理，提示用编译脚本更新。单文件判定是当前的启发规则，不是对所有自定义打包方式的完整识别。

新包要求运行时时，会检查标准 .NET 根目录中的 `Microsoft.NETCore.App` 主版本 10。客户端不会自动下载和安装 .NET。目标目录无写权限、文件被占用、Windows PowerShell 无法启动或运行时缺失都可能让安装失败，状态和 `psx.log` 用于排查。

源码：[更新界面状态](../PSdodo/ViewModels/MainViewModel.Updates.cs)、[检查/下载/安装脚本](../PSdodo/Services/UpdateService.cs)。

## 14 日志、设置、临时任务与数据边界（DIAG-LOG）

### 14.1 各种文件放在哪里

| 路径 | 内容 | 生命周期 |
| --- | --- | --- |
| EXE 同级 `psx.log` | 启动、导出参数、任务进度、错误、更新、托盘等诊断 | 追加写入；当前未实现按大小自动轮换 |
| `%APPDATA%/PsExporter/settings.json` | 默认参数、行为偏好、窗口位置 | 跨启动保存 |
| 同目录 `settings.json.tmp` | 写配置的暂存文件 | 保存后尝试清理 |
| `%TEMP%/psx_<编号>.psjs` | 本次注入后的 UXP 脚本，UTF-8 BOM | 成功后延迟尝试清理；失败/派发后取消可能保留 |
| `%TEMP%/PSexp/tasks/<编号>/result.json` | 脚本执行状态、文件列表、错误与诊断字段 | 成功后尝试删除任务目录；失败/超时/取消保留 |
| `%TEMP%/PSexp/<编号>/` | 快速/画板的中间图片 | 成功交付后尝试删除；失败可能保留 |
| `%TEMP%/psx_<编号>.log` | COM 探针的短期脚本日志 | 读取并透传后尝试删除 |
| `%LOCALAPPDATA%/PsExporter/updates/<编号>/` | 下载 EXE 与更新安装辅助文件 | 缓存，不与图片输出目录混用 |
| 用户选定输出位置 | 导出的 JPG/PNG | 正式输出，不自动删除整批旧结果 |

`%TEMP%` 取当前运行进程的实际系统临时目录，不应在文档或机器人中硬编码为某一个人的 `C:/WINDOWS/TEMP`。桌面、AppData 的实际位置也通过系统 API 获取。

### 14.2 psx.log 具体记录什么

- 启动 PID、可执行路径、程序集版本、日志路径。
- 导出请求的模式、输出位置预设与序列化参数快照。
- 任务编号 `[task=<编号>]`、EXE、TEMP、输出与回执目录。
- 注入参数摘要和脚本 SHA256，用于确认实际执行的是哪份脚本内容；不直接把整个脚本文本重复写入每条日志。
- 脚本是否成功派发、临时 `.psjs` 路径。
- 文件生成进度、完整回执、耗时与最终状态。
- 完整异常、阶段、路径、部分输出，失败诊断材料保留位置。
- 设置保存、位置恢复、托盘和自动更新相关信息。

日志行带本机时间和等级 Info/Warn/Error/Debug。写日志失败会被吞掉以免阻断核心流程，因此“没新增日志”可能是当前目录不可写、运行的是另一份 EXE，不能直接断言“代码根本没执行”。

### 14.3 给人或 AI 排查时怎样提供证据

从“开始导出请求”到同一任务结束的完整片段最有用，不要只截最后一句 Error。至少说明当前 EXE 路径/版本、Photoshop 版本、模式、格式、输出预设、完整错误、是否还有 Photoshop 操作在执行。

日志可能包含本地用户名、文档名、图层/切片名和完整路径。开源的是程序实现，不代表用户设计稿、日志、凭据或个人目录就属于公开素材。公开发 Issue 前可替换路径中的个人部分，同时保留目录结构、中文/空格等与复现有关的特征。

### 14.4 当前联网和本地处理边界

正常导出由本机 Photoshop 和本机文件系统完成，当前调用链没有把 PSD 或导出图片上传给更新服务器。自动更新会向配置服务器获取清单/EXE；没有从 `FileLogger` 自动上传日志的实现。

若用户自己把桌面或输出目录放进 OneDrive、网络共享等位置，后续同步由这些外部服务决定。不能把“应用不上传图片”扩展成“任何存储位置都不会同步”或“运行时绝对不联网”。

源码：[文件日志](../PSdodo/Core/Logging/FileLogger.cs)、[日志初始化](../PSdodo/App.axaml.cs)、[设置存储](../PSdodo/Services/SettingsService.cs)。

## 15 组合工作流：把功能放进真实设计过程

以下是由已有功能组合出来的使用建议，不是额外的自动化模块。每个方案仍由用户准备文档并点击执行。

### 15.1 客户即时预览

快速导出 + 桌面 + JPG 80 + 清晰图片名。适合反复发当前整体效果；开启自动改名避免把上一版预览盖掉。JPG 质量是折中起点，不代表对每种图像都最优。

### 15.2 同一作品多平台规格

一个 PSD 建多个命名画板，例如 `朋友圈_方图`、`公众号_横图`、`竖版海报`。全部画板 + 文档文件夹，得到按项目整理的一批输出。只改一张时，在 Photoshop 选中那张，切当前选中导出。

### 15.3 红蓝两套方案共享背景

公共背景用 Photoshop 真正背景，或放在主体下方的可见顶层 `排除_公共背景`；公共水印、透明边框放在主体上方的可见排除组。红、蓝方案分别为普通顶层组。一级模式逐个输出主体与这套公共内容的完整画布合成。隐藏排除组可存参考说明；普通隐藏方案组仍会输出。文档组织、八种玩法及源码证据见 [06 图层导出](#layers)。

### 15.4 只交付选中的几个组件

图层模式 → 选中图层，在 Photoshop 选择组件组，PNG 输出。选组得到组内当前可见合成；避免同时选组与子层后期待两份文件。需要紧贴素材边界的图片时，当前工具不自动裁边，可先调整文档组织或另行处理。

### 15.5 梳理复杂图层中的叶子素材

图层模式 → 全部图层，先给组内叶子图层取唯一名称；设计说明和不想独立交付的分支加“排除”。适合检查素材有哪些，而不是保证所有依赖混合/剪贴关系的层拆开后视觉一致。

### 15.6 电商长详情分块

先用 Photoshop 原生切片工具或参考线创建实际切片；给需要语义命名的片段命名，其余使用坐标顺序号。切片导出 + 自定义交付目录 + 统一前缀，可得到对应区域图片。超长整图可尝试这条路线，但仍先确认单片及文档容量受宿主支持。

### 15.7 同一项目连续导出留档

画板“文档文件夹”每轮新建带序号文件夹，适合保留整批历史；快速、图层、切片可用自动改名保留同名旧图。当前没有时间戳模板或版本备注管理；需自己记录各批结果含义。

### 15.8 固定交付路径供别人引用

固定自定义目录 + 画板覆盖文件夹 + 同名自动改名关闭。每次用同一画板名替换文件，适合外部文档引用固定图片路径。文档删除了画板或改了名时，旧文件不会自动删掉，应自行检查交付目录。

### 15.9 把 PSexp 当成边缘小工具

开启贴边收纳，放在工作屏外侧；需要时悬停展开，导出后移开收回。根据操作速度选 250/420/800ms 等待。重启可恢复收纳位置，减少重新摆窗。

### 15.10 主窗口让位，但保留任务入口

开启关闭后常驻，点 X 收起到托盘；任务继续，本机仍有入口。需要时单击图标或再次运行 EXE 恢复。真正退出用托盘退出；不要把“看不到窗口”理解成“程序已结束”。

### 15.11 不同文档跟随各自项目目录

默认位置保存为文档位置，自动同步开启；切换 Photoshop 文档后刷新并核对目录。它能减少手工改路径，但对于另存为后身份未变化的情况，仍需手动刷新确认。

### 15.12 开源复用和学习

开发者可以从 `ContinuousBorder` 学习连续曲率轮廓，从 `AnimatedSegmentTrack` 学习业务命令与动画绘制分离，从 UXP 回执学习异步跨进程任务通信，从原生切片脚本学习“一个副本 + 逐片回滚”的实现。复制前应理解依赖、宿主 API 和许可证，而不是仅替换项目名称就视为所有环境兼容。

## 16 开发原理、模块与脚本清单

### 16.1 技术栈和代码命名

应用使用 C#、.NET 10、Avalonia 12.1.1、Avalonia Skia 和 CommunityToolkit.Mvvm 8.4.2；依赖注入使用 Microsoft.Extensions.DependencyInjection。`[ObservableProperty]`、`[RelayCommand]` 由 MVVM 工具生成属性和命令。

产品名是 PSexp；代码目录/项目名保留 `PSdodo`，命名空间为 `PsExporter`，程序集名 `PSexpV3`。三者不一致是当前代码命名状态，不代表存在三个必须分别运行的软件。

### 16.3 为什么同时使用 COM/JSX 与 UXP/PSJS

探测侧：`PhotoshopDetector` 发现进程，Windows 路径下通过 `GetProcessesByName("Photoshop")`、进程版本/路径及注册表补充信息。`WindowsComBridge` 使用 `Photoshop.Application`，在 STA 线程调用 `DoJavaScript(..., ..., 1)` 执行 ExtendScript。

导出侧：`UxpScriptBridge` 写入 UTF-8 BOM 的临时 `.psjs`，`Process.Start` + `UseShellExecute=true` 通过 Windows 文件关联交给 Photoshop，支持 `require("photoshop")`、`require("uxp")`、`executeAsModal` 和 `batchPlay`。

两条链解决不同问题。COM 能探测不代表 `.psjs` 一定关联正确；`.psjs` 成功启动也不等于脚本保存完成。因此导出必须再依赖文件回执确认。

### 16.4 实际使用的脚本

| 相对 `PSdodo/Resources/Scripts/` 路径 | 运行环境 | 当前作用 | 主要返回 |
| --- | --- | --- | --- |
| `probe/document_info.jsx` | COM / ExtendScript | 活动文档名、目录、像素尺寸、画板数、是否有效原生切片 | JSON 字符串 |
| `probe/document_identity.jsx` | COM / ExtendScript | 轻量识别文档切换 | `文档ID\|文档名` 或 `none` |
| `probe/list_artboards.jsx` | COM / ExtendScript | 可列出画板的服务能力；当前主界面不展示独立勾选列表 | 画板列表 JSON |
| `export/quick_export.psjs` | UXP | 当前画布 `saveAs` | 由包装脚本收集文件 |
| `export/all_artboards.psjs` | UXP | `exportDocumentAsFileTypePressed` | 由包装脚本收集文件 |
| `export/selected_artboards.psjs` | UXP | `exportSelectionAsFileTypePressed` | 由包装脚本收集文件 |
| `export/receipt_task.psjs` | UXP 模板 | 包装前三种脚本的 `runExport()`，报告结果 | `result.json` |
| `export/layer_batch.psjs` | UXP | 一级、选中、全部图层，调整并恢复可见性 | 自己写 `result.json` |
| `export/native_slices.psjs` | UXP | 原生切片元数据、单副本循环裁剪回滚 | 自己写 `result.json` |

`list_artboards` 和模型中的 `SelectedArtboardIds` 不代表当前已经使用应用内 ID 勾选来驱动导出。实际选中画板脚本尊重 Photoshop 当前选择。

### 16.5 保留文件不等于当前执行路径

同目录还保留 `quick_export.jsx`、`all_artboards.jsx`、`selected_artboards.jsx`、`layers.jsx`、`slices.jsx` 等旧实现。`references/photoshop-scripts/` 还有历史 JS 参考。它们便于理解来源，但当前五条导出路径按上表走 UXP，不能把旧脚本逻辑当成正在运行的行为。

`ScriptLibrary` 按逻辑名优先找 `.psjs`，无匹配资源时再找 `.jsx`。这是资源选择规则，**不是 UXP 执行失败后自动用 ExtendScript 重跑**。图层明确调用 `export/layer_batch`，切片明确调用 `export/native_slices`，也不会因为旧 JSX 文件存在就改走它们。

`ExportFileWatcher` 保留了目录时间戳、长度和静默期判断能力，当前导出主链使用 `UxpTaskWatcher` 的明确完成回执。不能把旧观察器的 2 秒静默、120 秒超时介绍成当前任务的完成标准。

`LaunchPsCommand` 和进程检测器中还保留启动 Photoshop 的底层能力，`Program` 也有 `PSexpComProbe=1` 的开发诊断分支；当前主界面没有绑定出专用“启动 Photoshop”按钮，它们不应在用户介绍中被写成已经出现的可点入口。

### 16.6 探针的实现细节

`document_info.jsx` 在打开文档时读取名称、像素尺寸和 `doc.path`；未保存时路径读取失败，返回空目录。通过 Action Manager 枚举层描述的 `artboardEnabled` 来计数，读取 `slices` 元数据判定有效图像用户切片/图层切片。

探针局部读取失败会写警告，可能使对应能力识别为无；没有画板/切片的标志不一定等于用户文档里绝对不存在，也可能是宿主读取不兼容。完整错误与日志有助于区分。

COM 包装器去掉 `#target` 指令，捕获 `$.writeln` 到短期日志，约定 `__psx_result` 为返回值，再转为 `PsBridgeResult`。COM 取消和 UXP 取消都不能被视为任意时刻强制杀死 Photoshop。

### 16.7 模板参数与注入

脚本作为嵌入资源编译进应用，不要求用户手动把脚本复制进 Photoshop 插件目录。`ScriptLibrary.GetScript()` 从程序集读取原文；`ScriptParameterInjector.Inject()` 替换 `{{NAME}}` 占位符。字符串注入前转义反斜杠、单双引号和换行；缺少参数时保留占位符，便于暴露配置错误。

| 占位符 | 类型/来源 | 用途 |
| --- | --- | --- |
| `EXPORT_PATH` | 经过字符串转义、带尾分隔符的路径 | 快速/画板目标路径 |
| `EXPORT_FOLDER_URL` | `file:/` 加规范化路径、斜杠转换 | UXP 输出目录 Entry |
| `RESULT_FOLDER_URL` | 独立任务目录的 `file:/` URL | 回执目录 Entry |
| `FORMAT` | `jpg` / `png` | 格式 |
| `QUALITY` | 数字文本 | JPG 质量或特定 PNG 接口参数 |
| `RENAME` | JS `true` / `false` | 防覆盖自动命名 |
| `IMAGE_NAME` | 已转义字符串 | 快速命名在应用归并处理；图层脚本用作前缀 |
| `WITH_DOC_NAME` | 布尔字面量 | 图层默认前缀兜底 |
| `FILE_NAME` | 已转义字符串 | 切片前缀 |
| `RECURSIVE` | 布尔字面量 | 图层一级/图层模式 |
| `SELECTED_ONLY` | 仅递归图层模式有效的布尔值 | 选中对象/全部叶子对象 |
| `SCRIPT_BODY` | 已完成公共参数注入的脚本文本 | 放入快速/画板回执包装 |

服务还会设置兼容参数 `SLICE_MODE`，但当前选择切片还是图层脚本由 C# 显式分支决定，不靠同一脚本把图层冒充切片。

### 16.8 统一的任务回执协议

概念示例，字段路径使用虚构值；不是要求用户手工创建的配置：

```json
{
  "done": true,
  "success": true,
  "files": ["新品_红色款.png", "新品_蓝色款.png"],
  "error": "",
  "stage": "写入导出进度",
  "path": "file:/D:/Temp/PSexp/tasks/example/result.json"
}
```

公共判定字段为 `done`、`success`、`files`、`error`。脚本还可添加 `stage`、`path`、错误堆栈；切片附加 `slices`、临时文档 ID、复用标记、清理警告等诊断信息。应用会保留完整 JSON 到结果/日志，但并不是所有诊断字段都在界面逐项显示。

`files` 是输出目录下的文件名，不是随意的绝对路径。监视器过滤空名、目录穿越/带路径名、非 JPG/PNG 名称，并按大小写不敏感去重，再与真实存在的文件核对。完成成功要求脚本声明成功、至少一张图、有效存在文件数量与报告数量一致。它不逐张解码验证像素和视觉内容，因此“程序判定完成”仍不能代替用户检查图片是否符合设计意图。

### 16.9 故障材料保留策略

成功后清理回执目录与临时脚本，脚本清理还有约 2 秒延迟；失败保留任务目录和脚本，快速/画板交付成功才清理图片临时目录。应用派发后取消，不能删掉 Photoshop 还可能没读完的脚本。

清理失败一般不覆盖已经取得的导出结果；不能以“TEMP 里还有文件”直接判断整次导出失败，也不能以“派发成功”直接删掉仍在使用的任务文件。

## 17 常见问题与基于日志的排错

### 17.1 先确定故障发生在哪一层

```text
程序不能启动 → .NET、程序文件、权限、系统环境
文档识别失败 → Photoshop 进程、COM、活动文档、模态状态
开始按钮不可用 → 当前状态与目标条件
脚本派发失败 → .psjs 文件关联、临时脚本写入与启动
没有首份回执 → 脚本未执行或尚未创建回执、路径/权限/模态问题
回执中保存失败 → 看 stage + path + 完整 Photoshop 异常
脚本成功但最终失败 → 输出核对、最终归并、重命名/覆盖问题
图片生成但内容不对 → 当前文档/选择、可见性、组依赖、颜色/格式、切片边界
```

不要因为 Photoshop 菜单能手动导出，就认定软件侧的脚本派发、URL、临时目录、回执和归并链没有问题；也不要只有一句 `no such file or directory` 就直接猜 PSD 坏了。

### 17.2 常见现象、解释与处理方向

| 现象或文本 | 说明 | 优先查看/处理 |
| --- | --- | --- |
| 启动提示缺少 .NET | 默认包没有捆绑运行时 | 确认 .NET 10 x64 Runtime，不是只装其他主版本/架构 |
| Photoshop 未启动 / 未打开文档 | 当前探测无可用目标 | 在 Photoshop 打开文档，核对进程和刷新 |
| 找不到 `Photoshop.Application` | COM 类型没有正确获得 | Photoshop 安装/COM 注册、同机多版本、完整异常 |
| Photoshop 未响应或被中断 | COM 调用未完成 | Photoshop 是否有对话框、忙任务、权限或宿主异常 |
| 文档位置没有路径 | 文档未保存或路径尚未刷新 | 先保存并刷新，或改桌面/自定义 |
| 导出路径必须是完整路径 | 输入了相对目录 | 使用如 `D:/交付/项目A` 的完整目录 |
| 导出文件夹不可用或没有写入权限 | C# 预检创建/写入失败 | 权限、盘符、路径、目录是否被占用 |
| `no such file or directory` | 需要结合报错阶段定位 | 日志中的实际输出路径、`file:/` URL、TEMP、任务路径；确认运行的是哪份 EXE |
| Photoshop 未返回任务回执 | 30 秒内没有可解析的第一份回执 | `.psjs` 关联、脚本启动、回执目录权限、Photoshop 模态阻塞 |
| 枚举导出文件：Photoshop 未生成目标图片 | 包装脚本执行后没有枚举到 JPG/PNG | 实际脚本、保存命令、格式支持、临时输出目录；不能只证明 PS 菜单正常 |
| 等待 UXP 导出回执超时 | 整体超过当前 30 分钟等待上限 | Photoshop 是否还在执行、文档体量、任务回执最后阶段；不要立即删文件 |
| 图片已生成，但归并到导出目录失败 | 临时保存已完成，最终移动出错 | 最终路径权限、目标占用、名称、磁盘/跨目录移动 |
| 画板归并失败 | 部分画板移动失败 | 日志中的源/目标、覆盖参数、HResult 和部分文件 |
| 没有符合条件的图层 | 筛选后没有目标 | 一级/图层模式、背景属性、“排除”分支、当前选择 |
| 请在 Photoshop 中选择可导出的图层 | 选中模式没有有效对象 | 重新选普通层/组；背景和排除项不会独立导出 |
| 切片入口不可用 | 未识别有效原生切片或任务忙 | 确认创建了实际图像切片，刷新并看探针警告 |
| 没有可导出的原生用户切片 | UXP 运行时筛选为空 | 用户/基于图层切片、image 类型、非空边界；参考线本身不够 |
| 临时画布未恢复到完整尺寸 | 切片前安全检查失败 | 停止后续切片以避免错位，保留回执与宿主版本信息 |
| 恢复图层可见性失败 | 至少一层恢复出错 | 回 Photoshop 检查可见性，读取完整错误；不要立刻继续批量导出 |
| 关闭窗口后仍有图标/进程 | 后台常驻开启 | 托盘退出，或关闭“关闭后常驻” |
| 重启位置没有恢复 | 配置未成功保存、旧 EXE、屏幕适配或状态不在恢复范围 | 核对运行路径、设置 JSON、保存日志和屏幕变化 |
| 检查更新失败 | 清单或网络/校验异常 | 日志、服务器配置与实际清单，不能直接断言没有新版 |
| 总提示已是最新版本 | 远端版本不大于本机 | 新旧程序集版本、清单 version；同版本替换不算新版本 |
| 目录开发版请使用编译脚本更新 | 当前不是支持自动替换的单文件形式 | 用本地构建入口更新，勿只替换一个 EXE 丢掉依赖 |
| 更新清单缺少有效签名 / 签名无效 | 无法认证发布来源 | 核对签名发布流程与客户端内嵌公钥，不关闭验签；旧版与新版行为须区分 |
| 更新大小/SHA256/版本不一致 | 下载包与清单不匹配 | 发布者核对包和清单；客户端不会继续安装不匹配包 |

### 17.3 推荐的问题记录模板

```text
软件：当前 EXE 路径、界面版本；若是源码构建则附 Git 提交/修改状态
环境：Windows 版本、显示器/DPI（窗口问题时）、Photoshop 版本
文档：是否已保存、尺寸、画板/切片情况、颜色模式/位深（保存问题时）
功能：快速 / 全部画板 / 当前选中画板 / 图层具体子模式 / 切片
参数：输出预设和实际目录、JPG/PNG、质量、命名、自动改名
操作：在 Photoshop 选了什么，按顺序做了什么
预期：想得到哪些文件、怎样的图片
实际：状态完整错误、已经生成的文件、Photoshop 是否仍在执行
证据：同一 task 编号的完整日志片段、必要的 result.json 与脚本路径
```

优先提供能复现的简化文档结构，避免公开个人或客户完整设计文件。提交入口见 [GitHub Issues](https://github.com/linhuoxi/PSexp/issues)。

## 18 持久配置与本次导出参数参考

### 18.1 JSON 的表示规则

`SettingsService` 默认保存到 `%APPDATA%/PsExporter/settings.json`，采用 camelCase 字段名、缩进 JSON。枚举当前由默认 JSON 序列化器保存为数字，没有注册字符串枚举转换器。

| 枚举 | 数值 |
| --- | --- |
| `ExportDestination` | 0 文档位置、1 桌面、2 自定义 |
| `ExportFormat` | 0 JPG、1 PNG |
| `AppThemeMode` | 0 浅色、1 深色、2 跟随系统 |
| `ExportPathOption`，本次参数 | 0 图片直出、1 新建文档文件夹、2 复用文档文件夹 |

通常应从界面修改；需要手工改时先真正退出软件并备份，以免运行中的保存覆盖手改值。下表用于理解实现，不代表每个字段都有界面编辑入口。

### 18.2 AppSettings 全字段

| JSON 字段 | 新安装默认/模型默认 | 作用与保存规则 |
| --- | --- | --- |
| `defaultExportPath` | 系统“文档”目录，作为保留的自定义路径 | 只有设为默认时用当前自定义输入更新；不等于当前文档位置的实际解析结果 |
| `defaultDestination` | 新安装为 0；模型可空 | 默认输出位置来源；旧配置缺少时按保留路径兼容处理 |
| `defaultFormat` | 0 | 启动格式；设为默认才更新 |
| `defaultQuality` | 80 | 启动 JPG 质量；读取时限制到 1–100 |
| `defaultAutoRename` | true | 同名策略；修改会保存 |
| `photoshopExePath` | null | 供启动 Photoshop 的底层能力使用；当前界面无路径设置入口 |
| `pollingIntervalMs` | 3000 | 历史保留配置；不是当前轻量文档同步计时器的实际间隔 |
| `layerExportWithDocName` | true | 手动前缀空时用文档名兜底 |
| `layerExportRecursive` | false | 一级图层/图层模式，修改保存 |
| `layerExportSelectedOnly` | true | 图层模式默认选中图层，修改保存 |
| `layerExportShowHint` | false | 旧配置兼容字段，当前不再用于 Photoshop 导出完成提示窗 |
| `autoUseDocNameAsPrefix` | false | 图层有效前缀优先采用文档名 |
| `themeMode` | 0 | 主题偏好 |
| `startAlwaysOnTop` | false | 用户置顶偏好，反映本次切换后的持久值 |
| `autoRefreshOnActivated` | true | 当前界面“自动同步文档”的底层字段 |
| `enableEdgeSnap` | true | 贴边收纳 |
| `autoCheckForUpdates` | true | 定时检查更新 |
| `autoDownloadUpdates` | true | 发现新版后后台下载 |
| `closeToTray` | true | 关闭窗口隐藏到托盘 |
| `enableBlankDrag` | true | 空白区域拖窗 |
| `enableQualityHoverAnimation` | true | 质量条悬停动效 |
| `documentSyncIntervalMs` | 1200 | 仅接受 800/1200/2000，其他值启动回 1200 |
| `dockRetractDelayMs` | 420 | 仅接受 250/420/800，其他值启动回 420 |
| `windowPlacement` | null，保存后为对象 | 展开参考位置、屏幕与收纳状态 |
| `windowWidth` | 440 | 正常窗口宽度 DIP；正常规范化最小 360 |
| `windowHeight` | 660 | 正常窗口高度 DIP；正常规范化最小 600 |

首次无配置时创建默认输出来源为文档位置。旧配置缺少来源字段时，保留已有自定义路径的兼容行为；不要简单假设升级后的每位用户都会自动改成文档位置。

加载 JSON 失败时当前实现回到默认配置，没有给损坏文件提供界面修复器。尺寸为非有限数、非正值时用默认值，正常尺寸最小值再规范化；窗口打开时还会根据屏幕工作区进一步限制。

### 18.3 WindowPlacementState 字段

| JSON 子字段 | 含义 |
| --- | --- |
| `x`、`y` | 普通展开位置的物理像素坐标；收纳时保存其展开参考位置 |
| `workX`、`workY` | 保存时所在显示器工作区原点 |
| `workWidth`、`workHeight` | 保存时工作区物理像素尺寸 |
| `scaling` | 保存时缩放比例，默认 1 |
| `isDocked` | 是否为贴边收纳态 |
| `edge` | 字符串 `None` / `Left` / `Right` / `Top` / `Bottom` |

坐标字段和窗口宽高单位不同，恢复时必须经过缩放换算；不能把 440 DIP 一律当 440 物理像素直接相减。边缘采用字符串是这个记录类型的具体设计，不改变其他枚举数字保存的规则。

### 18.4 ExportSettings：任务快照，不是完整用户配置

| 字段 | 用途 |
| --- | --- |
| `ExportPath` | 本次已经解析的实际输出根目录 |
| `DocumentName` | 当前文档名，画板子目录等使用 |
| `Format`、`Quality`、`AutoRename` | 本次图片格式、质量、文件冲突策略 |
| `FileName` | 切片文件前缀，非切片任务传空 |
| `ImageName` | 快速图片主体或已经决策后的图层有效前缀 |
| `LayerExportWithDocName` | 图层前缀为空时的文档名兜底 |
| `LayerExportRecursive`、`LayerExportSelectedOnly` | 图层目标规则 |
| `LayerExportShowHint` | 兼容字段，当前不触发 PS 提示窗 |
| `ExportPathOption` | 画板存放方式 |
| `ExpectedFileCount` | 已知时的预期数；不能代替脚本实际文件清单 |
| `SelectedArtboardIds` | 保留模型字段，当前 UI/选中脚本不按它驱动目标 |

Snapshot 将共享路径预设解析为具体路径，之后的命名与保存不应反过来覆盖用户保留的自定义目录。`ExportSettings` 用于一次任务，`AppSettings` 用于下次启动，二者不能混为一个“所有参数都自动记住”的承诺。

### 18.5 更新清单字段

| JSON 字段 | 作用 |
| --- | --- |
| `name` | 固定产品标识 `PSexp` |
| `version` | 远端版本字符串，应与待下载 EXE 内置版本一致 |
| `download_url` | 受限 HTTPS EXE 下载地址 |
| `sha256` | 对最终上传 EXE 计算的 64 位十六进制摘要 |
| `size` | EXE 精确字节数 |
| `changelog` | 更新说明纯文本 |
| `requires_dotnet` | 是否需要客户端在安装前确认共享 .NET 10 Runtime；默认 true |

这些功能字段同时作为 `signed_update.payload` 内的认证内容。外层另有 `signed_update` 对象，包含 schema、key_id、algorithm、Base64 payload 和 Base64 signature；新客户端忽略外层同名平铺功能字段。签名覆盖带域前缀的原始 UTF-8 payload 字节，详见 [签名协议](更新安全与发布签名.md)。

此表是协议说明。真正发布时 size、sha256、版本必须来自实际成品；发布私钥只留本机，不能上传服务器或写入源码。

源码：[应用配置模型](../PSdodo/Models/AppSettings.cs)、[位置模型](../PSdodo/Models/WindowPlacementState.cs)、[任务参数](../PSdodo/Models/ExportSettings.cs)、[设置服务](../PSdodo/Services/SettingsService.cs)。

## 19 编译、发布、Git 和文档维护

### 19.1 公开编译入口

仓库根目录 `编译.bat` 需要 .NET 10 SDK：先构建并运行 .NET 自测，全部成功才发布 Windows x64 单文件，默认 `--self-contained false`、不混淆、不裁剪、保留单文件压缩。成品名称来自项目 `AssemblyTitle`，放在脚本旁；中间文件位于 `%TEMP%/PSexp-compile/`。

脚本构建失败或自测失败不算可交付编译成功；即使磁盘已有旧 EXE，也不能据此判断本次产物已更新。这个公开入口不自动上传 GitHub，不自动建立 Release，不承担作者本地私有发布脚本的全部职责。

目录开发版保留多份 DLL、运行配置 JSON 和本机图形依赖，便于快速增量迭代；正式单文件把应用依赖捆绑进 EXE，某些本机库启动时可自行解压。移除 .NET 运行时仍不等于 Avalonia、Skia 等依赖全部消失，不能承诺 EXE 只剩很小的业务代码体积。

### 19.2 作者外层目录的本地脚本

作者本机外层还有“一键编译测试.bat”“一键编译发布.bat”等辅助入口，它们不是当前公开源码仓库的组成部分。克隆者不能假设一定存在。

截至本说明编写时，外层测试入口按当前用户会话与应用进程名停止运行中的 PSexp，等待退出，再发布不压缩的目录开发版，成功后自动启动；默认不跑自测，可用 `PSexpRunSelfTests=1` 显式启用。它不会因为要关闭 PSexp 就一起结束 Photoshop。

外层正式发布入口涉及版本、GitHub 与服务器协调，需看它实际调用的本地发布工具和配置；本文不把私有机器路径、服务器凭据或外层脚本假设为开源使用条件。介绍“运行哪个脚本是否会发版”时，先区分公开 `编译.bat`、本地测试入口与本地正式发布入口。

### 19.3 Git、GitHub Desktop、Releases 与 OneDrive 的关系

Git 管源码提交；GitHub Desktop 是操作本地 Git 仓库的客户端；GitHub 网站展示远端仓库、标签、Release 和附件。它们不是点击 Fetch 就互相同步所有文件的一套网盘。

- 修改本地代码/文档后，需要 Commit 才形成提交，Push 才把提交传到远端。
- Fetch 获取远端引用和提交信息；不会把未提交修改上传，也不会代替 Pull 合并到本地工作分支。
- 把源码 Push 到 GitHub 不会自动编译 EXE，也不会自动更新服务器 `version.json`。
- Releases 的附件、版本标签、标题和时间由发布动作管理；正式发布应使用新版本号，而不是只覆盖一个旧附件期待所有展示和客户端检测一起变化。
- OneDrive 是文件同步工具，和 Git 的分支/提交历史不是同一机制。桌面如果由 OneDrive 接管，桌面上的项目仍可能同步；放到桌面并不能普遍证明离开 OneDrive。
- 在另一台机器使用项目，通常通过 Git 克隆/拉取源码，单独安装 Git/GitHub Desktop、SDK/Runtime、Photoshop 并配置本机环境；复制一个文件夹不等于这些程序和关联都已安装。

这一节解释操作边界；本文没有执行提交、推送、发布或改变 OneDrive 设置。

### 19.4 公开内容与排除内容

适合纳入仓库：应用源代码、内嵌 Photoshop 脚本、测试源码、项目文件、公开编译入口、README、开发/界面/功能文档与许可证。

当前 `.gitignore` 排除 `bin/`、`obj/`、PDB、日志、测试结果、根目录生成 EXE、构建输出目录、IDE 状态、环境配置和多种证书/密钥扩展，以及个人记录目录。它不是对任何可能的秘密文件的自动识别器，发布前仍需看实际改动。

EXE 通过 Releases 等分发入口交付；`psx.log`、个人 `settings.json`、临时回执、客户 PSD、服务器登录配置和私钥不因“源码开源”而需要进仓库。本文只描述公开客户端可见的更新协议，不公开服务器认证材料。

### 19.5 测试源码与实际验证状态

`tests/PSdodo.Tests` 是独立测试程序，运行应用不需要它。包含 .NET 自测、`uxp-layer-batch.test.cjs`、`uxp-receipt.test.cjs` 等行为测试。额外 Node 测试模拟 Photoshop 对象和文件系统，不能完全代表真实 Photoshop 的图片渲染或 Windows 动画行为。

本文编写没有执行这些测试，也没有实机导出验证。后续维护可按 [开发指南](开发指南.md) 运行需要的检查；是否通过要依据当次输出记录，不能由“仓库有测试”推导为“当前代码测试全通过”。

### 19.6 文档与代码如何一起维护

发生以下改动时应同步更新本手册和 AI 导览：导出目标规则、命名优先级、排除语义、原生切片筛选、格式/质量映射、覆盖策略、默认值、任务超时/取消、窗口恢复、更新源/协议或设置文案。

维护顺序建议：

1. 找实际调用代码，而不是只看旧注释或参考脚本。
2. 更新对应稳定功能编号下的行为与限制。
3. 调整示例、表格、FAQ 和机器人推荐句。
4. 保持相对源码链接有效；对容易重构的内容优先引用文件和方法名，不固化会漂移的行号。
5. 标清适用源码/发布版本及是否经过实际验证。
6. 发布时将文档与实际二进制功能对齐；尚未发布的行为不能被机器人说成旧版已经具备。

事实优先级：用户正在使用的版本对应源码和运行证据 → 同版本文档 → 当前主线文档 → 历史参考。发现冲突时明确版本差异，不用听起来更好听的介绍掩盖不确定性。
